# レイヤーフォルダーのドラッグによる親変更

文書の位置付け: **採用済み設計・導入時の実装記録。文中の旧版・件数・当時の未実装表記は記録時点のもの。** 現在の対応範囲と保存契約は[実装状況](implementation-status.md)を正とする。

2026-10-19。基準は[統合設計](scada-integrated-design.md)、[整理フォルダー](layer-folders-design.md)、[配置の所属ドラッグ](layer-drag-design.md)。Astraのレビューを反映する。導入時のProject 0.12.0と既存のmove-folderを使い、保存契約は変更しない。

## 移動の意味

フォルダー名・アイコンから、そのフォルダーと配下の階層をドラッグする。保存する変更は対象フォルダー1件のparentIdだけとし、配下の所属ID・座標・サイズ・表示・ロック・描画順、フォルダーのorderと配置選択を保持する。現在の選択をフォルダードラッグへ巻き込まない。

展開記号と操作ボタンは移動元にしない。終了直後のclickで開閉せず、移動したフォルダー自身の開閉状態も保持する。配下にlocked・非表示があっても、既存の親変更Modalと同様に許可する。継承ロック・継承表示・幾何グループではない。

## 移動先と案内

同じ画面／共有定義のフォルダー直下、またはドラッグ中のルート領域へ移動する。自己・全子孫・16段を超える移動先はhoverから禁止し、強調とmoveカーソルを出さない。深さは移動先の深さと移動する部分木の高さの合計で判定する。禁止先の付近でも端スクロールは継続できる。挿入線・兄弟順変更・Ctrlによる複製は追加しない。

フォルダー名と配下を移動する旨、配下の配置数・非表示数、移動先パスまたは禁止理由を案内する。現在の親へのdropは履歴を増やさない。成功時は移動先とその祖先を展開し、検索は保持する。検索から外れた場合は通知し、検索を黙って解除しない。

## 入力保護と再検証

配置の所属dragと判別型のセッションを共用し、DataTransferには専用MIMEのtokenだけを入れる。開始時に対象ID・元の親・世代／所有先を固定し、drop時に移動先を固定する。入力確認後は存在・循環・部分木の深さと元親を再検証し、別の親へ変わった古い操作を適用しない。

未適用入力の取消では入力とモデルを保持する。入力の確定と親変更はそれぞれ独立したUndoになる。native dragendは既に確認待ちとなったdrop意図を消さない。未dropのtokenはEsc・終了・window blur・タブ／画面／所有先／モード／パネル表示の変更で無効になる。キーボード操作は既存の親変更Modalを残す。

## 受入条件

TypeScriptで配下集計・自己／子孫・部分木の深さ・移動元親の変化を確認する。ブラウザで両テーマのnative drag、locked／非表示配下と選択・座標の保持、閉じた状態、ルート／同値、Undo／Redo／JSON、入力確認・取消・不正値、古いtoken、共有定義と検索を確認する。
