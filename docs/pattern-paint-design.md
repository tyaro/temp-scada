# 矩形・楕円の繰返しパターン

文書の位置付け: **採用済み設計・導入時の実装記録。文中の旧版・件数・当時の未実装表記は記録時点のもの。** 現在の対応範囲と保存契約は[実装状況](implementation-status.md)を正とする。

2026-10-20（日本時間）。ユーザー指定の「メッシュ＝斜線・網掛け・点などの繰返しパターン」を、[描画拡張の計画](scada-graphics-runtime-extension-design.md)とAstraの読取専用レビューから具体化する。**Project 0.19.0で保存・UI・共通描画へ接続済み**。[実装記録](development-plan.md#pattern-paint-progress)を参照。0.18.0の線形グラデーションに続く工程であり、自由メッシュグラデーションや画像タイルを含めない。

## 最初の範囲

矩形・楕円の塗りに「斜線／交差線／点」を加える。枠線・Polyline・Textは単色を維持する。保存は既存の `fill.enabled` と `FillPaint` を拡張し、配置rootの色を再導入しない。

```ts
{
  type: "pattern";
  kind: "hatch" | "crosshatch" | "dots";
  spacing: number;
  size: number;
  angle: number;
  foreground: PaintColor;
  background: PaintColor | null;
}
```

間隔はdesign unitで、平行線に垂直な距離／点の中心間距離。隙間の幅ではない。初期値は間隔12、線幅1、点径3。斜線・交差線の角度45°、点0°。保存制約は `2 ≤ spacing ≤ 1024`、`0 < size ≤ min(64, spacing / 2)`、角度0以上360°未満とする。sizeとspacingの相関はTSとRustの意味検証を共用ケースで照合する。色は6桁HEX、αは有限0〜1。

## 座標と描画

図形左上のlocal座標を固定原点にし、原点移動UIは初回不要。角度0°は水平線、90°は垂直線、正方向は時計回り。gradientの角度は色の進行方向なので、欄名を「線／格子の角度」として区別する。

SVGのpatternUnits／patternContentUnitsはuserSpaceOnUse。図形resizeでは間隔・太さを保ち、繰返し数が変わる。配置回転で模様も回り、Symbol配置の拡縮では内部の図形・模様を共に拡縮する。pattern IDは描画インスタンス単位とし、複数Symbol・ミニマップ・サムネイルで衝突させない。

交差線の2方向は一つの前景として合成し、交点だけαを濃くしない。タイル端の線の二重描画、点の欠け、回転時の継ぎ目は実ピクセルで検証する。pattern背景は任意のRGB＋α、nullは透明であり、塗りなし・前景α0と区別する。配置opacityは完成した図形／Symbolへ既存規則で一度適用する。

縮小時に細かな模様が潰れる可能性がある。重要な状態は模様だけに依存させず、数値・文字等を併用する。図形のhit・外形・回転pivot・資産Storeは変えない。

## 入力と切替

既存の「塗りと枠線」フォーム内で、種類→間隔／線幅または点径→角度→前景RGB／α→背景ありなし／RGB／αを編集する。説明は短くし、必要な詳細はヘルプへ置く。Inspector内の小さな市松背景の見本で透明設定を確認できるようにする。図面の背景を勝手に変えない。

初回のsolid→patternは現在の色・α、gradient→patternは始点の色・αを前景に使い、背景なしとする。pattern→solid／gradientの初回は前景の色・αを引き継ぐ。フォーム内で訪問済みの種類へ戻るとその未適用入力を保持する。背景なしへ適用すると保存値はnullにするが、フォーム内の背景ありなし往復は入力を保持する。

塗りなしでもpattern設定を保持する。blurで一部確定せず明示適用し、Enter・IME・対象切替・他フォームの事前検証・Undoを共用する。狭いパネルでも横にあふれず、縦スクロールで全入力と適用へ到達できるようにする。

## Symbolと一括色

定義色はpatternをそのまま描く。単色Symbolは前景・存在する背景のRGBだけを置換し、α・間隔・角度・太さを保持する。背景なしを新たに生成しない。前景と背景が同色でも、半透明なら重なりでαが変わるため模様が残る。不透明な同色同士なら模様は見えなくなる。これは通常の合成結果であり、元定義を変えない。

有効patternを含むRGB一括編集は全件拒否し、単独の塗り設定へ案内する。無効patternと有効枠線なら枠線だけを変更できる。単色Symbol配置のRGB変更は維持する。

## 受入条件と後続

TS／Rust／schema・生成例を同じ次期形式へ揃える。半透明の交差部・透明背景・タイル境界・細長い楕円・回転・resize・ズーム・Symbol複数配置を実描画で確認する。塗りなしと種類のdraft往復、一括色拒否の全件不変、JSON・図形clipboard v1・画像混在v2・Undo往復を検証する。

画像タイル、任意網点、自由ハッチ原点、pattern付き枠線、多点編集は後続。patternは画像資産を追加しない。設備context・Action・認証・正式Runtimeはこの工程へ混ぜない。

## タイル計算の先行実装

`pattern-paint.ts`で3プリセットの単一fill pathを生成する。交差線の2つの長方形を同方向のnonzero pathとして塗り、交点へ前景αを重ねない。点はセル内に収まる円とし、セル境界で分割しない。間隔・太さの有限性と相関制限を検証する。

単体3件、Chromium3件で整数／小数の形状・上限・不正値、半透明の交点・セル境界・複数セルの点の実ピクセルを確認した。交点と線のαはいずれも128/255で揃う。この時点では0.18.0を維持し、アプリからpatternを編集・保存できる状態の完成とはしない。

## 実装と実画面

0.19.0で既存の塗りフォームと共通Primitiveへ接続した。見本も同じPrimitiveを使い、入力が不正なら見本を消して理由を表示する。Project・Undoは明示適用まで変えない。塗り種類、模様の種類ごとの太さ・角度、背景の有無の入力を適用前まで保持する。背景なしへ適用するとbackgroundはnullにする。旧0.18.0は自動移行しない。

Astraの読取専用レビューでも、draft・保存比率・α合成・共通色の原子的拒否を照合した。単色Symbolでも前景と背景の半透明αは通常どおり重なり、同色でも濃淡が残る。
