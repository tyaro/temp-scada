# 実Hub書込みの受入手順（段階3の操作 O4d）

状態: **手順のみ。未実施**。2026-11-20作成（日本時間）。[段階3の操作の設計](../design/runtime/operation-stage3-design.md)のO4（実Hubの安全番地での確認、元値へ戻す手順の記録）を、Windows実機で受け入れるための手順と記録様式である。実施はユーザー作業（またはユーザーの許可を得たClaude Code）とし、結果はこの文書の末尾（§6）へ日時つきで追記する。様式は[C5受入記録](real-hub-c5-acceptance.md)に倣う。

## 1. 範囲と前提

- **対象**: このWindows PCの既存Hub（`127.0.0.1:8722`）と、C0・C3と同じR系PLC（R08、接続`plc_slmp`）。Hubは0.3.0-alpha.4（2026-11-20ユーザー申告）。
- **書込み契約の確認**: Hubが書込み契約`write_contract_v1`を持つかは、アプリが`/api/v1/status`で確かめる。持たないHubへは書かず、`hub_unsupported`（「Hub が書込みに対応していません」）と出る（[設計](../design/runtime/operation-stage3-design.md)§11-8）。この表示が出たら受入は止め、Hubの版を記録して報告する。
- **安全範囲**: [C0の記録](real-hub-c0.md)のC3の節にある、R08ENCPUの`D3000-4999`／`M1000-2000`。
- **書込み先は、この受入専用の新しいタグだけ**。ほかのタグ（`D3000`、`SCADA_C3_*`など）へは書かない。

| 外部名                           | 番地  | 型            | 用途                       |
| -------------------------------- | ----- | ------------- | -------------------------- |
| `plc_slmp.group1.SCADA_O4_D4010` | D4010 | i16（number） | 数値の書込み（範囲0〜100） |
| `plc_slmp.group1.SCADA_O4_M1510` | M1510 | bit（bool）   | 運転・停止のボタン         |

どちらもHubで有効・**書込み可（writable）**にする。

- **PLCへの書込みは、ユーザーの許可を得てから行う**。許可の前は§2.1〜2.5（読取と準備）までに留める。PLCへ直接接続しない。Hubの停止・再起動・構成変更（受入用タグの追加と、§2.6のキーの発行・失効を除く）も行わない。
- **起動元とデータの場所**: [C5受入記録](real-hub-c5-acceptance.md)§1と同じく、アプリ・`real_hub_read`は通常のterminalから起動する（パッケージ版デスクトップアプリの配下だと`%LOCALAPPDATA%`がリダイレクトされることがある）。
- **権限**: 書込みの端末設定（キーの登録・削除・再開・最小間隔）はAdmin（認証無効モードの合成Adminを含む）。初期設定中（`initializing`）はログインなしで書込みできる。
- **確認の観点（オーナー注記）**:
  - 「タスク起動＝取り消さない境界」と「Hubへの到達確認」を混同しない。送信を始めた後にキーを登録し直しても送信は取り消されず、結果は届いた後に判断する。画面の「送信中」は到達済みを意味しない。
  - `WriteRejected`は「書込みは成立していません」と出る（送る前の拒否と、送って失敗を分けない）。
  - 結果不明（`uncertain`）は自動で再送しない。「書けたか分かりません。現在値を確かめてください」を見たら、現在値を読み戻してから人が判断する。

## 2. 準備

### 2.1 版とビルド

1. `work`の最新を取り、commit IDを記録する。#334・#335（操作履歴の窓・`operationList`）がマージされている版かどうかも記録する（§3の該当項目に注記がある）。
2. 通常のterminalで、READMEの`--runtime <Projectのファイル>`で起動する（C5と同じ）。開発起動は`pnpm dev`と、`cd apps/banto-scada/src-tauri && cargo run --locked -- --runtime <Projectのファイル>`。

### 2.2 `operations.db`と認証DBの退避

アプリを止めてから、端末のデータフォルダー（`%LOCALAPPDATA%\temp-scada`）直下の次をコピーして別名で退避する。

- `operations.db`（`-wal`・`-shm`があれば一緒に）。**形式6（#333、O4a）は形式5までのRuntimeでは開けない**。受入後に前の版へ戻す場合は、この退避を戻す。
- 認証DB（`scada-auth.sqlite3`）。`hub-read.json`・`installation-id`は触らない。

### 2.3 Hubへのタグ2件の登録

§1の表の2件を、次のどちらかでHubへ登録し、有効・書込み可にする。

- SCADAの「Hub登録用CSVを書き出す」（[設計](../design/equipment/equipment-register-design.md)の該当節）。`examples/real-hub-write.project.json`をEditorで開き、機器の表から書き出して、Hubの「タグのCSVインポート」で取り込む。addressは空欄で出るので、D4010・M1510を埋める。`writable`列は`write`を持つslotなので`true`で出る（取込み後にHubの画面で書込み可になっていることを確かめる）。
- Hubの管理画面で直接追加する。

登録後、catalog revisionを記録する。

### 2.4 書込み前の元値の確認

```bash
cargo run --locked -p scada-host --example real_hub_read -- plc_slmp.group1.SCADA_O4_D4010 plc_slmp.group1.SCADA_O4_M1510
```

2件が`tag_present=…:true`、`quality=good`、`source=real`であることを確かめ、**元値（D4010の数値、M1510の0／1）を記録する**。§3.9で戻す値になる。

### 2.5 受入用Project

[`examples/real-hub-write.project.json`](../../examples/real-hub-write.project.json)を使う。

- 機器種別「O4d 書込み受入」に二つのslot。`setpoint`（number、書込みの見出し「D4010 設定（0〜100）」、入力の下限0・上限100）と、`command`（bool、見出し「M1510 運転指令」、ボタン「運転」=true・「停止」=false）。
- 画面「書込み受入」に機器`O4D-1`（シンボル）とD4010の現在値の文字。機器`O4D-1`のbindingは上表の2タグ。
- 画面切替ボタン（`operationList`）は入れていない。現行のschemaは`operationList`を受け付けないので、**#335のマージ後に足す**（`navButton`の行き先を操作履歴にする）。

### 2.6 Hubでの書き用キーの発行

上流の運用ガイドの節[「SCADA の端末に読み用と書き用の 2 本のキーを発行する」](https://github.com/tyaro/banto-industrial/blob/6a08efbb76b50e6094f88f6dc91c46b8c4a8ecc3/docs/hub/banto-hub-operations.md)に従い、書き用キーを発行する。**キーの値はこの文書にも記録にも残さない**（実施記録には発行した事実と日時だけを書く）。

## 5. 記録様式

```text
### O4d <番号> <日時 JST>
- commit: <work のcommit ID>  Hub: <版> catalog revision: <n>
- 操作: <行ったこと>（キーの値は書かない）
- 画面: <表示の要約・文言>
- 読み戻し: <real_hub_read の関係する行>
- 判定: 合格 / 不合格 / 未観測 / 未実施（理由）
```
