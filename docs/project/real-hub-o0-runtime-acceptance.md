### 6.2 `auth_setup`（最初の管理者の作成）— O0 の受入から外した（2026-11-20 ユーザー判断）

- 認証無効モード（初期設定のフェーズ）の間、host の `auth_setup` は断る。最初の管理者は **Editor の「運用へ移行…」で作る**（設計 §10 の 2 の実装時の補足）。Runtime の「最初の管理者を作成」は、認証が有効で管理者がいない場合（通常の経路では起きない）だけに出る。
- 「運用へ移行」は**認証無効モードへ戻せない**。移行後はこの端末の Editor の記録の変更・警報の ACK などにログインが要る。認証の作業は 2026-10-18 の指示で延期中で、ローカル編集はログイン不要のまま維持する方針である。
- 設計 §9 の実機の受入の項目には `auth_setup` も運用への移行も無く、#279 の範囲外に「認証」がある。**2026-11-20 のユーザー判断で #279 の受入から外し、認証の作業を再開するときの受入へ移した。**
- 下の手順 3 は Editor の運用への移行の確認で、Runtime の `auth_setup` を受け入れたことにはならない。Runtime の `auth_setup`（認証が有効で管理者がいない場合）は別の確認として計画する。
- 認証の作業を再開して行うときは、通常の端末の状態を上書きして書き戻すのではなく、**隔離した試験環境**（別の Windows 利用者・試験用の端末や VM など、`%LOCALAPPDATA%\temp-scada` を共有しないところ）で行う。下は手順の骨子:
  1. 試験環境に release ビルドを置き、初期設定のフェーズから始まることを確かめる（アプリのデータフォルダーが空、または受入用に作ったもの）。
  2. 引数なしで Editor を起動し、上端の認証の札で「フェーズ: 開発・初期設定」「ログインなし（認証無効モード・管理者）」を確かめる。Runtime で起動したときは「運用への移行は Editor で行ってください」の注記だけが出ることも確かめる（§10 の 2）。
  3. Editor で「運用へ移行…」を押し、受入用の利用者名とパスワード（使い捨て）で最初の管理者を作る。「運用へ移行しました。管理者としてログインしています。」とフェーズ「運用」を確かめる。
  4. 試験環境のデータフォルダーは受入の後に消し、通常の端末へは持ち込まない。
