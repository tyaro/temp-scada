# ブラウザ全画面での表示確認

2026-10-20（日本時間）。[拡張計画](scada-graphics-runtime-extension-design.md#kiosk)で先行可能とした開発用の表示確認を実装する。運用kioskの起動・配布・認証・OS設定は後続とし、[アクセス方針](access-policy.md)の運用移行や匿名監視を実装済みにしない。

## 表示と終了

表示プレビューのツールバーに「全画面で表示確認」を置く。利用者のクリックからブラウザのFullscreen APIを呼び、documentElement全体を対象にする。小窓やBanto Modalも全画面領域の中へ残す。ヘッダーと左のProjectパネルは一時的に隠し、終了ボタン・モード切替・画面タブ・小窓の起動を残す。

「全画面を終了」とブラウザ標準のEscで戻れる。Escのブラウザ既定を独自に乗っ取らない。終了イベントで通常配置を戻す。画面切替では全画面を維持し、小窓は既存方針どおり閉じる。編集へ戻る／Project世代差替えでは、自分が開始した全画面を終了する。

全画面はProject・Undo・パネル配置設定へ保存しない。編集モードの手動倍率・位置を上書きせず、プレビューは領域に合わせて表示する。全画面の前後で残る小窓は領域変更へ追従してclampする。

## 許可待ちと失敗

対応しないブラウザでは、理由をtitleへ出してボタンを無効にする。許可失敗はメッセージを出し、通常の表示と小窓を保持して再試行できる。別の要素が全画面を使っている場合は勝手に終了しない。

`preview-fullscreen.ts`が要求中・所有状態・Project／modeのscopeを管理する。要求中にscopeが変わってから遅れて成功した場合は終了する。modeやProjectを往復しても古い要求を復活させない。古い要求の後始末が終わるまで新しい要求を重ねない。終了に失敗した時は終了ボタンとブラウザのEsc経路を残す。破棄後の通知・古いエラーを新画面へ出さない。

## 検証

単体6件で、scopeなし・通常開始と終了・標準終了イベントへの同期・API非対応・別要素の全画面・要求失敗と再試行・終了失敗・scope往復後の遅延応答・破棄後の終了と通知抑止を確認する。

実ブラウザでは両テーマのネイティブFullscreen API、ヘッダーと左パネルの一時非表示と復帰、小窓とBanto Modal、保存内容不変、標準終了イベント、編集復帰／Project差替えによる終了、許可失敗・非対応表示を確認する。OSやブラウザのkiosk設定、再起動時の監視復帰、対象モニター／DPIの固定は対象外。

TypeScript全599件、型チェック（エラー・警告なし）、本番ビルドが成功した。実ブラウザは全画面5件＋小窓10件の15件が成功した。全492件の再実行ではない。Fullscreen APIと終了イベントは実ブラウザで確認し、ネイティブEscはブラウザ既定へ委譲する。既存のJSチャンク500kB超の警告は継続する。
