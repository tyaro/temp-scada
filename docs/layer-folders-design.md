# レイヤーフォルダーの設計

状態: **Astraレビューに基づく次の実装仕様。未実装**。現行Projectは0.7.0。モデル追加時は0.8.0へ更新し、Rust／TypeScript／Schema／現行サンプルを同期する。基準は[統合設計](scada-integrated-design.md)。

## 目的と範囲

タンク・ポンプ・配管等を見つけやすくする整理用フォルダーを追加する。幾何的なグループではなく、所属によって座標・サイズ・表示順・Symbol参照・表示／ロックを変えない。

最初の操作は作成・名前変更・親変更・配置の所属変更／解除・空フォルダー削除。フォルダーのクリックは開閉とフォーカスだけで、配下の一括選択を発生させない。フォルダー単位の表示・ロック・変形・再帰削除・ドラッグ並べ替えは後続。

## 保存契約

画面と共有Symbol定義に必須の`folders: LayerFolder[]`を追加し、空配列を許容する。各配置には任意の`folderId`を追加する。未指定は所有先の直下。所属は最大1つとする。

```ts
interface LayerFolder {
  id: UUID;
  name: string;
  order: number;
  parentId?: UUID;
}
```

- フォルダーIDもProject全体で一意のUUID v7。名前は識別子として使わず、同名を許容する。
- 名前は単一行・最大200コードポイント。前後空白を保存せず制御文字を拒否する。UIは既存の200 UTF-16単位の入力上限を維持する。
- `order`は非負のJS safe integerで、所有先のフォルダー全体で一意。配置の描画orderとは独立する。
- `parentId`は同じ画面／共有定義のフォルダーだけを参照する。自己参照・循環・参照切れ・所有先をまたぐ参照を拒否する。
- `folderId`も同じ所有先へ限定する。JSONのnullは保存せず、解除時は属性を削除する。
- 1所有先256フォルダーまで、階層は直下を1として16段まで。親変更では子孫を含む最大深さを検証する。Rust／TSで同じ共有fixtureを使う。
- 親変更で座標や配置のorderを変えない。新規フォルダーは最大folder orderの次へ追加し、初回はフォルダー自体の並べ替えUIを追加しない。

## コマンドと履歴

所有先は画面IDと任意の共有定義IDで明示し、既存編集コマンド・検証・Undoへ接続する。

| 操作     | 動作                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------- |
| 作成     | 名前と親を指定。親なしは直下。UUIDを発行する。                                                       |
| 改名     | trim後の同値はno-op。名前は参照IDへ流用しない。                                                      |
| 親変更   | 自己・子孫を移動先へ選べない。実行直前にも循環と深さを検証する。                                     |
| 所属変更 | 配置ID配列と移動先folder ID／直下を指定。空・重複・参照切れを拒否する。全対象を1コマンドで変更する。 |
| 所属解除 | folderId属性を削除する。同じ所属ならno-op。                                                          |
| 削除     | 子配置も子フォルダーもない場合だけ。非空なら理由を示して拒否し、自動移動や再帰削除をしない。         |

配置の所属変更は編集ロックに従い、locked混在は全体を拒否する。hidden配置は件数を示して対象へ含める。フォルダー自身の改名・親変更は整理構造の変更であり、配下のロックを継承しない。

Projectを変更する操作は既存draft guardを使う。実行直前に読込世代・所有先・対象IDを確認する。取消・検証失敗では変更せず、成功操作はUndo1回。Undo／Redoではフォルダーと所属を整合した状態で戻す。

## 複製とクリップボード

- 同じ所有先での配置複製は所属を保持する。
- 画面／共有定義の複製・Symbol独立コピーでは、フォルダーID・親ID・配置のfolderIdも対応付けて再発行する。配置ID・所有先IDの既存再発行も維持する。
- 図形のコピー断片は直下へ配置する形式とする。コピーした最上位配置のfolderIdを除き、断片の画面foldersを空にする。元データは変更しない。
- 依存する共有Symbol定義のフォルダー構造は保持する。同じProjectで定義を再利用する場合は現在の定義を使い、別Projectへ定義を取り込む場合はフォルダーIDと参照も再発行する。
- 貼付先のフォルダーを暗黙に選ばず、直下への貼付をヘルプへ明記する。
- 新規配置は直下とし、フォルダーのフォーカスだけで配置先を変えない。

0.7.0の自動移行は追加しない。既存0.1.0読込経路を残す場合だけ、現行形式への変換でfoldersの空配列を明示する。内部の組込Symbolも現行の空フォルダーを明示する。

## レイヤーUI

画面ルートの下にフォルダーと配置を表示する。各階層ではフォルダーをfolder order順、配置を描画order順で表示する。フォルダーの階層順と描画順は独立すると示し、「一覧で下なら常に前面」という案内を混在させない。

検索欄は1行のまま、作成アイコンを隣に置く。フォルダーの右クリックは子作成・改名・親変更・空削除。配置の右クリックは所属変更・解除を用意する。変更先では所有先・直下・階層パスと対象件数／非表示件数を示す。同名の移動先を選び分けられる表示を用意し、処理は必ずIDで行う。

作成時は親を明示して選べるようにする。親変更の候補から自己・子孫を除外し、深さを超える候補も選択不可にする。初回の移動先選択はモーダル／リストで十分とし、ドラッグ移動を先行させない。

フォルダーの開閉はローカルの作業状態。検索では配置の名前・種類・ID・Text・外部名に加えてフォルダーパスを使い、一致項目と祖先を表示する。フォルダー名に一致した場合はその配下も探せるようにする。検索中の強制展開を通常の開閉状態へ保存せず、検索解除で元へ戻す。空フォルダーの名前一致も表示する。

キャンバス・タグ／Symbol使用先から配置を選んだ場合、検索は消さず、検索条件内の対象なら祖先を開いてレイヤーで辿れるようにする。条件外なら既存の検索外選択の案内を維持する。フォルダーを閉じても配置選択・Inspector・入力は保持する。

名前・親・移動先を指定するモーダルは、確定までProjectを変更しない。既存入力の保護を通してから開く。キャンセルで元のフォーカスへ戻す。IME中のEnterを確定に使わず、モーダル内のキーを背景の保存・Undo・全選択へ流さない。古い読込世代の応答を適用しない。

Renderer・ミニマップ・Symbolサムネイルはフォルダーを描画や変形の条件に使わない。タグ参照・Symbol使用先の参照関係も保持する。

## 受入確認

- Rust／TS共有fixture: 有効な階層、同名、全図形と共有定義内の所属、ID重複、親／所属の参照切れ、所有先越境、自己参照・循環、256件／16段の境界、名前のUnicode空白・制御文字。
- コマンド: 混在ロックの原子的拒否、hiddenの所属変更、非空削除の拒否、同値no-op、親変更と子孫深さ、Undo／Redo、JSON往復。
- 複製／clipboard: 再発行後の全参照、同一Projectの定義再利用、別Projectへの定義取込、直下への貼付、元データの不変。
- UI: 親変更の候補、対象表示、検索解除時の開閉復帰、検索外選択、右クリック・キーボード・IME、未適用入力・取消、両テーマと狭幅。
- フォルダー整理の前後で、描画結果・配置の座標と重なり・タグ読取投影が変わらないこと。
