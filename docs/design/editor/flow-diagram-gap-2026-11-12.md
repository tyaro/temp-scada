# 目標のフロー図と現状の差分（2026-11-12）

作成: 2026-11-12（日本時間）。状態: **洗い出し・実装計画（§5.1 は2026-11-12のオーナー回答を反映。Hub の構造体の扱いは未決）**。実装の採用や完了を示さない。

## 1. 目標

オーナーが示した実プラントの SCADA 画面8枚（焼却炉の全体、給排水、吸収塔、搾汁・前処理・糖化・発酵・培養の各設備）の水準のフロー図を、Designer で描けて、運転画面として表示できること。参照画面は Git 管理外で、このリポジトリへは画像・切り抜き・トレースを入れない。以下は文章だけで書く。

参照画面に共通する要素:

- 系統ごとに色分けした密な配管（実線・破線の信号線）、矢印、分岐・合流、交差。
- 機器の記号: 弁（XV／TV／FV／LV／PV）、ポンプ、ブロワー、槽、塔、サイクロン、熱交換器、撹拌機、斜めのコンベヤ、スクリューフィーダー。
- 槽の液位の塗りつぶし。
- 単位つきの数値表示（Hz、mm、m3/h、kPa、℃、pH など）。
- HH／H／L／LL／AH／SL の警報限界の小札（状態で色が変わる）、`*` 印、番号の小札。
- 状態色のセル（運転中、一括故障、連動運転選択中など）。
- 表: 工程表（開始・完了・未、時刻）、メッセージ表示、設定値・PV の表。
- 画面外への接続矢印（CWS、CWR、LPS、CIPS、ATM など）。
- 画面の枠: 上端に画面名・最新の警報・アラーム履歴／ブザー停止／印刷・日時、下端に現在の画面を強調した画面切替ボタン列と前後ボタン。
- 機器のステータスは、ビット割付（状態ごとに1つの bool）とワード割付（1つの整数ワードの値、またはワード内のビットで状態を表す）の両方がある。

## 5. 実装計画（段階1・2）

2026-11-12 のユーザー指示で、このセッションでは計画だけを立て、実装は会話のクリア後に始める。

- 各区切りは小さい PR にし、検証が通った区切りで日本語の Conventional Commits でコミットする。
- リリース前の Project は後方互換を保証しないので、旧形式の移行は作らない。
- 現行形式の schema（`crates/scada-model/schema/project.schema.json`）・Rust（`crates/scada-model`）・TS（`apps/banto-scada/src/lib/project.ts` ほか）・サンプル（`examples/`）・試験を同じ PR で揃える。
- 参照画面の画像はどの PR にも入れない。

### 5.1 決めたこと（2026-11-12 のオーナー回答と Fable への相談の結果）

- **状態の定義の置き場所**: 機器種別（EquipmentType）の slot に持たせる。Project 共通の「状態表」の資源は作らない。
  - Symbol 定義が持つのは、slot の名前と型だけ。
  - 機器インスタンスが持つのは、slot への実タグの割付だけ。
- **ビットかワードか**: 案件ごとに違い、どちらもある。案件の中では、モータ・バルブなどの割付ルールはほぼ統一されている。
  - 割付が大きく違う機器は、利用者が別の機器種別として定義する。
- **該当する信号がない機器**（例: 故障の信号がないモータ）: その slot は未割付のまま使う。状態の評価では「なし」（false 扱い）とし、未割付を異常として表示しない。
  - これは slot ごとに「未割付を許す」を指定したときだけにする。
- **Hub への反映**: 当面は、SCADA から書き出して Hub 側で適用する。SCADA は Hub の admin キーを持たず、Hub へは読取専用のまま。
- **タグ名の規約**: 設備ベンダーの PLC アドレスや信号名には頼れない。ただし Hub のタグ名は Hub に登録する側が付けるので、ベンダー間の揺れを Hub 側で吸収し、命名規則（機器ごとの接頭辞＋機器種別で共通の末尾）を統一できる（2026-11-12 オーナー）。一括割付は、一覧の表での編集を基本にし、命名規則による自動入力をその補助として加える。
- **未決**: Hub の構造体を「登録の補助」のままにするか、タグ一覧の概念として持つよう上流に求めるか。開発ユーザーから見ると SCADA と Hub に区別はない。モデルは Hub の構造体に依存させず、後で「構造体の参照1つ」の割付へ置き換えられる形にしておく。
- **ビットが複数当たるとき**: 状態の行を上から評価し、最初に当たった行を表示する。
- **C6 との前後**: 並行して進められる（コードを共有しない）。

### 5.2 段階1-A 状態の多値表示（ビット・ワード）

すべて Hub の構造体がなくても進められる。

- **A1 モデル**（2026-11-12 実装。形は[機器種別の編集](../equipment/equipment-type-editing.md)の「状態の定義」）:
  - slot の型に `state` を加える。`state` の slot は、元の値の種類（`value`＝ワードの値、`bits`＝ワード内のビット）・行（match・文字・色。上が優先）・該当なし（文字・色）を持つ。
  - `bool` の slot には、任意で true／false の文字と色を持たせる。
  - slot に「未割付を許す」を加える。
  - 状態の定義を持てるのは機器種別の slot だけとし、Symbol 定義の `readSlots` は名前と型だけを持つ（型の対応を検査する）。
  - schema・Rust・TS・検査（ビットは 0〜31、重複、型の対応）・サンプルを揃える。
- **A2 評価**（2026-11-12 実装。`apps/banto-scada/src/lib/slot-state.ts`）:
  - 純関数 `evaluateSlotState(slot, reading)`。`slot` は機器種別の slot、`reading` は既存の読取表示結果（`SlotPresentation`。品質と型付きの値を持つ）。
  - 整数でない値・絶対値が 2^53 以上・Good 以外の品質・型の不一致は「不明」（理由は既存の欠測の語）。「未割付を許す」の slot が未割付なら、bool は false、state は「該当なし」（`none: true` を付ける）。
  - `bits` は 0〜31 のビットだけを見る（負の値は 2 の補数）。結果は文字・色・当たった行の番号と SIM の有無。number の slot は対象外。
- **A3 表示**（2 つの PR に分ける）:
  - A3a 文字（2026-11-12 実装）: Symbol 内の slot に結合した文字は、機器種別の slot に定義（`state`、または `boolDisplay` を持つ `bool`）があれば、既知の状態で定義の文字を出す（SIM は前置、空の文字は空のまま）。不明は従来の欠測の文字（理由）を出す。許可された未割付は「なし」（bool は false、state は該当なし）の文字を出し、詳細には「未割付（なしとして表示）」と書く。色は変えない。試験: `e2e/slot-state-display.spec.ts`（モックの読取）。
  - A3b 色（2026-11-12 実装）: Text の `boolColors`（Symbol 側の true／false／取得不能の 3 色）を廃止し、`stateColors: { unknownColor }`（「状態の色に従う」指定と取得不能の色 1 つ）に置き換えた。対象は宣言済みの `bool`／`state` slot に結合した共有Symbol内の Text。既知の状態の色は機器種別の定義だけが持ち、既知で色なし（`boolDisplay` のない bool）は通常の色、不明は `unknownColor`。図形・配管の `stateColor` はこの Text を配色元とし、同じ規則で解決する（既知で色なしは図形自身の通常の色）。サンプルの true／false の色は機器種別の `boolDisplay` へ移した。schemaVersion は 0.37.0 を据え置き、旧形式の読込・移行は作らない。試験: `e2e/slot-state-color.spec.ts`（モックの読取）、`state-color.test.ts`。仕様: [slot表示Textの状態の色](../graphics/bool-text-colors.md)。
- **A4 編集 UI**（2026-11-12 実装）: 機器種別の slot 編集に、状態の行の編集を加えた。操作は[機器種別の編集](../equipment/equipment-type-editing.md)の「状態の行の編集」。試験: `e2e/slot-state-rows-edit.spec.ts`、`slot-display-edit.test.ts`。
- **A5 割付の一覧表**（2026-11-12 実装）:
  - 行が機器インスタンス、列が slot の表で、実タグを編集する。機器種別ごとに表を切り替える。
  - 表計算ソフトからの貼付けと、タグ一覧との照合（未解決の表示）、適用前の差分確認を備える。
  - ベンダーの I/O 一覧を CSV で取り込めるようにするのは、この後の候補。
  - 実装: 「プロジェクト」→「機器」→「割付の一覧表」で開く Modal。操作と規則は[機器台帳](../equipment/equipment-register-design.md#割付の一覧表)。試験: `equipment-binding-table.test.ts`、`e2e/equipment-binding-table.spec.ts`。
- **A5b 命名規則による自動入力**（2026-11-12 実装）:
  - 機器種別の slot に、タグ名の末尾の既定値を持たせる。
  - 機器インスタンスに接頭辞（`connection.group.` と名前の接頭）を1つ入れると、全 slot のタグ名を組み立て、タグ一覧と照合して A5 の表へ入れる。
  - 保存するのは従来どおり slot ごとのタグ名。見つからないタグは表で示し、手で直せる。
  - 実装: slot の任意の `tagSuffix`（schema `$defs.equipmentSlot`、TS `EquipmentSlot`、機器種別の編集の「タグ名の末尾」）。接頭辞は保存せず、割付の一覧表の「接頭辞」列と「接頭辞から入れる」で入れる（純関数 `prefixFill`）。`allowUnassigned` の slot で一覧にない名前は空欄（採用・未割付）にする。規則は[機器台帳](../equipment/equipment-register-design.md#接頭辞から入れる2026-11-12a5b)。schemaVersion は据え置き。試験: `equipment-binding-table.test.ts`、`equipment-type-editing.test.ts`、`examples/equipment-cases.json`（Rust・TS 共通の契約）、`e2e/equipment-binding-table.spec.ts`。
- **A6 画面上の直接結合**（優先度を下げる）: 機器を介さない文字・配管は、bool の色と文字だけに絞る。多値の表示は機器を介することを基本にする。
- **A7 Hub 登録用の一覧の書き出し**（2026-11-12 実装）: 機器種別と割付から、統一した命名規則のタグ名で Hub に登録する一覧（CSV か JSON）を書き出す。
  - 実装: 割付の一覧表の「Hub 登録用 CSV を書き出す」。Hub のタグ CSV 取込みと同じ 19 列・BOM・CRLF で、タグ一覧にない名前（新規登録分）だけを書き出す。外部名は書き出しでだけ `接続.グループ.タグ` に分け、分けられない名前は一覧で示して除く。address は空欄で、利用者が埋めてから Hub で取り込む。規則は[機器台帳](../equipment/equipment-register-design.md#hub-登録用-csv-を書き出す2026-11-12a7)。試験: `hub-tag-csv.test.ts`、`e2e/equipment-binding-table.spec.ts`。

### 5.3 段階1-B〜F

- **B 数値の書式**（2026-11-12 実装）:
  - 数値を出す文字に `format: { decimals, unit }` を持たせる。単位は Project に文字で保存し、編集時にタグ一覧の単位を初期値にする。
  - `presentNumeric` が書式を受ける。slot の数値も同じ書式を使う。
  - 実装: Text の任意の `format`（schema `$defs.numericFormat`、小数桁 0〜6・単位 1〜16 文字、タグか slot の結合が要る）。Good の数値だけに使い、欠測には単位を付けない。Inspector の「数値の書式」で編集する。schemaVersion は据え置き。仕様: [数値の書式](../graphics/numeric-format.md)。試験: `numeric-format.test.ts`、`examples/numeric-format-cases.json`（Rust・TS 共通の契約）、`e2e/numeric-format.spec.ts`。
- **C 液位**（2026-11-12 実装。B の書式は使わず、数値は書式付きの Text を重ねて出す）:
  - 図形 `level` を追加する（`min`・`max`・向き（上・右）・塗りと地の色）。
  - Symbol の中では number の slot に、画面では直接結合に従う。
  - 品質不良・範囲外のときは塗らずに、その状態を示す。
  - 実装: 塗りの色は配置の `fill`、地は任意の `background`。結合は Text と同じ `binding`／`slotBinding`。欠測は灰の破線枠、範囲外は橙の枠と三角。schemaVersion は据え置き。仕様: [液位](../graphics/level.md)。試験: `level.test.ts`、`examples/level-cases.json`（Rust・TS 共通の契約）、`e2e/level.spec.ts`。
- **D 部品と反転**（依存なし。反転と部品は別の PR にする）:
  - `BaseObject` に左右・上下反転を加える。回転・選択枠・接続点・Symbol の中の扱いを揃える。
