# 左ペインの整理とメイン領域の作業タブ（Issue #223）

作成: 2026-11-17（日本時間）。状態: **設計案（未実装）**。対象: Designer の編集モード。

Issue [#223](https://github.com/tyaro/temp-scada/issues/223) の方針「左ペインは機能・画面・対象を選ぶナビゲーションに絞り、入力・登録・設定はメイン領域で行う」を具体化する。根拠は [UX精査](ux-review-2026-11-11.md) の L-1・L-6・F-5 と §5.5。ドッキング基盤は作らない（AGENTS.md の 2026-10-18 方針）。2026-11-17 にオーナーが「メイン領域の作業タブ」の方式を選んだ。同日、Fable の通しレビューを反映した。

## 2. 方式: メイン領域の作業タブ

### 2.1 見た目と開き方

- 中央の上端に、横スクロールする画面タブの並びと、**スクロールしない固定領域**の作業タブを並べる（画面は最大100枚あり、同じスクロールに置くと作業タブが隠れるため）。作業タブは「機器」「警報」「プロジェクト設定」の3種類で、各1枚まで。
- タブの構造は画面タブ（`nav`＋`aria-current="page"` のボタン）に揃える。閉じる（×）はタブの外の兄弟ボタンにする。フォーカスは、作業タブを開いたら作業画面の見出しへ、閉じたら直前に選んでいたタブへ移す。
- 作業タブを選ぶと、中央のキャンバス・ルーラー・下部の帯（タグ参照・お気に入り）の代わりに、その作業画面を中央の全幅で表示する。画面タブを選ぶとキャンバスへ戻る。
- 左ペインのプロジェクトタブはツリーだけにする:
  - 「画面」「タグ参照」「シンボル」は現状のまま。
  - 「機器」: 件数と「機器台帳を開く」、見出しに「＋」（作業タブ「機器」を新規登録の状態で開く）。UX精査 §5.5 の図は「行を選ぶと右に詳細」だが、一覧を左ペインと作業画面に二重に置くと、部品の参照（`bind:this`）と追跡フォームが二重になるため、一覧は作業画面だけに置く。
  - 「設定」: 「プロジェクト設定」「警報」「記録希望設定」の行。前2つは作業タブを開き、記録希望設定は既存の Modal を開く（無効条件は §1 の現行を引き継ぐ）。
- 既存の入口も作業タブへ向ける: Inspector の「関連機器の台帳設定を開く」は作業タブ「機器」で対象機器を選ぶ（§3 の W12）。メニュー（ファイル／表示）に作業タブを開く項目を足す。

### 2.2 作業画面の中身

- **機器**: 左に機器一覧（検索・ページ・機器一覧／機器種別の切替）、右に選んだ機器の登録／割付フォームと使用先。機器種別の表示では右に種別の編集フォーム。割付の一覧表は当面いまの Modal のまま、ここから開く。
- **警報**: 左に定義の表、右に選んだ定義の詳細フォーム。
- **プロジェクト設定**: プロジェクト名、運転表示の設定、記録希望設定を開くボタンを縦に並べる。
- 既存の部品（`EquipmentLibrary`・`EquipmentTypes`・`AlarmSettings` とフォーム）は中身を変えずに置き場所を移し、2列の配置は作業画面側の CSS で作る。左ペインの浮動化や幅の変更で作業画面の幅が変わるため、1列へ戻す切替は container query（作業画面の幅 720px 未満を目安）で行う。

## 3. 状態と不変条件

状態の所有は、作業タブの一覧と選択中のタブを持つ小さな controller（`controllers/work-tabs.svelte.ts`）に置く。App は次の導出値と、モード・定義編集・draft の接続だけを持つ。汎用のタブ／ドッキング基盤にはしない。

- `workTabsShown` = 編集モード、かつ Symbol 定義の編集中でない。作業タブの並びと作業画面はこの値から表示する。
- `canvasActive` = 編集モード、かつ作業タブを選んでいない。キャンバスに向く操作の可否はこの1つで判定する。

| ID  | 不変条件                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| W1  | 作業タブの開閉・切替は Project・revision・Undo 履歴を変えない。作業タブで確定した変更は既存の `edit()`／`submitForm` を通り、Undo／Redo・入力検証・保存は現行と同じ。                                                                                                                                                                                                                                                                                                                                                                         |
| W2  | **メイン領域の表示の切替（作業タブを開く、作業タブ⇄画面タブ、作業タブ同士、作業タブを閉じる）はすべて `transition`（`drafts.allow`）を通す。** 現行の画面の切替（`openScreen`→`drafts.allow`）と同じく、離れるフォームの未適用入力は確定し、明示適用のフォーム（機器の新規登録・警報の定義など `data-explicit-apply`）では確認を出す。非表示の作業画面に未適用入力を残さないので、後のキャンバス操作で突然確定されたり、W6 で作業タブへ引き戻されたりしない。作業画面を開く操作も通すので、Inspector の未適用入力が W9 で隠れたまま残らない。 |
| W3  | 開いている作業タブの DOM は、非選択中も破棄せず `hidden` で保持する。目的は一覧の選択・検索条件・ページ・機器一覧／種別の表示を残すことで、未適用入力の保持ではない（W2 により非選択の作業画面に未適用入力はない）。                                                                                                                                                                                                                                                                                                                          |
| W4  | `canvasActive` でないとき、キャンバスを変更する入口を理由付きで無効にする: グローバルのショートカット Ctrl+A／G／D（入力欄以外にフォーカスがあると発火する）、ツールバー（`EditToolbar`）、メニューの編集・挿入・倍率・「選択範囲を表示」、左ペインの「レイヤー」「部品」からの配置とドラッグ。Delete・F・クリップボード（`clipboardScope`）と矢印（`CanvasWorkspace` 内）は既にキャンバス内に限定されているので変更しない。Undo／Redo と保存などのファイル系は全体に効く（W11）。                                                            |
| W5  | キャンバスは作業タブの表示中も破棄しない。非表示（寸法0）の間は ResizeObserver の通知で view（フィット倍率・スクロール）を更新しない。画面タブへ戻るときは既存の `rememberEditView`／`restoreEditView` で倍率・中心・選択を復元する。                                                                                                                                                                                                                                                                                                         |
| W6  | `revealDraftForm` は、対象フォームが作業画面にあればその作業タブを選ぶ。対象が Inspector・画面設定・タグの置換（下部の帯）なら、先に画面タブへ切り替える（W10）。入力検証で拒否されたフォームへのフォーカス移動も同じ。                                                                                                                                                                                                                                                                                                                       |
| W7  | 作業タブは `workTabsShown` から導出して表示する。`mode` は `changeMode` 以外にも、使用先へ移動（edit へ）・新規作成（edit へ）・機器の読取詳細（preview へ）で変わり、初期値は preview なので、各経路に個別の処理を足さない。プレビューへ移る経路は現行どおり `drafts.allow` を通り、作業タブは閉じずに隠すだけにして、編集へ戻ったら開いていた作業タブと選択を戻す。Project の採用（`adoptProject`）では作業タブをすべて閉じる。読込の取消・失敗では閉じない。再起動時は開かない（保存しない）。                                             |
| W8  | Symbol 定義の編集中は作業タブを隠す（W7 と同じく閉じずに隠し、定義の編集から戻ったら復元）。これは**現行より絞る意図的な変更**で、定義の編集中も使えていたプロジェクト名と機器台帳も、定義の編集を終えるまで使えない。左の「設定」「機器」の行とメニュー項目は「Symbol 定義の編集中は使えません」と理由を示して無効にする。                                                                                                                                                                                                                   |
| W9  | 作業タブの表示中は Inspector を隠す。`showInspector`（パネル配置の保存と `toggleAuxPanels` が使う）は書き換えず、表示を `showInspector && canvasActive` からの導出にする。浮動の Inspector も隠す。表示メニューの Inspector の項目は作業タブの表示中は無効にする。                                                                                                                                                                                                                                                                            |
| W10 | キャンバス・Inspector・下部の帯を対象にする遷移と reveal は、先に画面タブを選ぶ: 機器の「使用先」（`openSymbolUsage`）、Symbol 定義の編集（`openDefinition`）、画面の追加（`addScreen`）、左の画面一覧・タグ参照一覧を開く、Inspector・画面設定・タグ置換の `revealDraftForm`。                                                                                                                                                                                                                                                               |
| W11 | 作業タブの表示中に Undo／Redo でキャンバス側（画面・配置）が変わったときは、画面タブへ切り替える。作業画面の内容（機器・警報・Project 設定）だけが変わったときは、作業タブのままにする。                                                                                                                                                                                                                                                                                                                                                      |
| W12 | 外から作業画面の対象を選ぶ操作（Inspector の「関連機器の台帳設定を開く」の `showEquipment`、タグ選択の開閉の確認 `isTagPickerOpen` など）は、部品のマウントが前提なので「作業タブを開く → `tick` → 部品の処理」の順にする。これまでの左ペインへの reveal（`expandTreeAncestors`・`activePanel = "project"`）は削除する。                                                                                                                                                                                                                      |

## 5. 決定事項

Fable のレビューの推奨に沿って、次の案で進める（オーナーが別の判断をしたら改める）。

1. 左ペインの「機器」は件数・開くボタン・「＋」だけにし、一覧は作業画面に置く（§2.1）。
2. 作業タブの表示中は Inspector を隠す（W9）。
3. 割付の一覧表（Modal）は対象外。`bindingTableOpen` がメニューを止める現状のまま。作業画面へ取り込むかは WT3 の後に別 Issue で決める。
4. 記録希望設定・トレンド定義などの既存 Modal を作業タブへ移すか（UX精査 L-6）は対象外。記録希望設定は「設定」ツリーと記録メニューの両方から同じ Modal を開く。

5. W8 のとおり、Symbol 定義の編集中はプロジェクト名・機器台帳も使えなくする（2026-11-17 オーナー確認。使い勝手を見て後から改める可能性がある）。
