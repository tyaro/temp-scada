作成: 2026-11-17（日本時間）。状態: **実装中**（WT0・WT1a・WT1b・WT2 を 2026-11-18 に実装。WT3 以降は未実装）。対象: Designer の編集モード。

Issue [#223](https://github.com/tyaro/temp-scada/issues/223) の方針「左ペインは機能・画面・対象を選ぶナビゲーションに絞り、入力・登録・設定はメイン領域で行う」を具体化する。根拠は [UX精査](ux-review-2026-11-11.md) の L-1・L-6・F-5 と §5.5。ドッキング基盤は作らない（AGENTS.md の 2026-10-18 方針）。2026-11-17 にオーナーが「メイン領域の作業タブ」の方式を選んだ。同日、Fable の通しレビュー2回とオーナーのレビュー（PR #243）を反映した。

## 2. 方式: メイン領域の作業タブ

### 2.1 見た目と開き方

- 中央の上端に、横スクロールする画面タブの `nav` と、**スクロールしない別の `nav aria-label="作業タブ"`** を並べる（画面は最大100枚あり、同じスクロールに置くと作業タブが隠れるため）。作業タブは「機器」「警報の定義」「プロジェクト設定」の3種類で、各1枚まで（「警報の定義」は既存の Modal「警報の端末設定」と区別する名前）。
- タブの構造は画面タブ（`nav`＋`aria-current="page"` のボタン）に揃える。作業タブの選択中は画面タブの `activeId` を `null` にし、`aria-current="page"` が2つにならないようにする。閉じる（×）はタブの外の兄弟ボタンにする。フォーカスは、作業タブを開いたら作業画面の見出しへ、閉じたら直前に選んでいたタブへ移す。
- 作業タブを選ぶと、中央のキャンバス・ルーラー・下部の帯（タグ参照・お気に入り）の代わりに、その作業画面を中央の全幅で表示する。画面タブを選ぶとキャンバスへ戻る。
- 左ペインのプロジェクトタブはツリーだけにする:
  - 「画面」「タグ参照」「シンボル」は現状のまま。
  - 「機器」: 件数と「機器台帳を開く」、見出しに「＋」（作業タブ「機器」を新規登録の状態で開く）。UX精査 §5.5 の図は「行を選ぶと右に詳細」だが、一覧を左ペインと作業画面に二重に置くと、部品の参照（`bind:this`）と追跡フォームが二重になるため、一覧は作業画面だけに置く。
  - 「設定」: 「プロジェクト設定」「警報の定義」「記録希望設定」の行。前2つは作業タブを開き、記録希望設定は既存の Modal を開く（無効条件は §1 の現行を引き継ぐ）。
- 既存の入口も作業タブへ向ける: Inspector の「関連機器の台帳設定を開く」は作業タブ「機器」で対象機器を選び、メニュー「プロジェクト名を変更」は作業タブ「プロジェクト設定」のプロジェクト名へフォーカスする（W12）。メニュー（ファイル／表示）に作業タブを開く項目を足す。

### 2.2 作業画面の中身

- **機器**: 左に機器一覧（検索・ページ・機器一覧／機器種別の切替）、右に選んだ機器の登録／割付フォームと使用先。機器種別の表示では右に種別の編集フォーム。割付の一覧表は当面いまの Modal のまま、ここから開く。
- **警報の定義**: 左に定義の表、右に選んだ定義の詳細フォーム。
- **プロジェクト設定**: プロジェクト名、運転表示の設定、記録希望設定を開くボタンを縦に並べる。
- 既存の部品（`EquipmentLibrary`・`EquipmentTypes`・`AlarmSettings` とフォーム）は中身を変えずに置き場所を移し、2列の配置は作業画面側の CSS で作る。例外として、左の「＋」から新規登録の状態で開くために `EquipmentLibrary` に export を1つ足す（現行の外部 API は `showEquipment`・`isTagPickerOpen` だけ）。
- 左ペインの浮動化や幅の変更で作業画面の幅が変わるため、1列へ戻す切替は container query（作業画面の幅 720px 未満を目安）で行う。ウィンドウの最小幅は、native が 960px（`tauri.conf.json`）、Web は 700px 以下で全体が1列の既存レイアウト。どちらでも3つの作業タブと×に手が届き、作業画面を縦スクロールで最後まで操作できること。

## 3. 状態と不変条件

状態の所有は、作業タブの一覧と選択中のタブを持つ小さな controller（`controllers/work-tabs.svelte.ts`）に置く。App は次の導出値と、モード・定義編集・draft の接続だけを持つ。汎用のタブ／ドッキング基盤にはしない。

- `workTabsShown` = 編集モード、かつ Symbol 定義の編集中でない。作業タブの並びと作業画面はこの値から表示する。
- `canvasActive` = 編集モード、かつ（作業タブを選んでいない、または `workTabsShown` でない）。キャンバスに向く操作の可否はこの1つで判定する。
- controller は2つの入口を持つ: 利用者の操作用の `open`／`select`／`close`（`transition` を通す）と、ゲートを通さない同期の `selectNow`（W2 の例外だけが使う）。

## 5. 決定事項

Fable のレビューの推奨に沿って、次の案で進める（オーナーが別の判断をしたら改める）。

1. 左ペインの「機器」は件数・開くボタン・「＋」だけにし、一覧は作業画面に置く（§2.1）。
2. 作業タブの表示中は Inspector を隠す（W9）。
3. 割付の一覧表（Modal）は対象外。`bindingTableOpen` がメニューを止める現状のまま。作業画面へ取り込むかは WT3 の後に別 Issue で決める。
4. 記録希望設定・トレンド定義などの既存 Modal を作業タブへ移すか（UX精査 L-6）は対象外。記録希望設定は「設定」ツリーと記録メニューの両方から同じ Modal を開く。

5. W8 のとおり、Symbol 定義の編集中はプロジェクト名・機器台帳も使えなくする（2026-11-17 オーナー確認。使い勝手を見て後から改める可能性がある）。
