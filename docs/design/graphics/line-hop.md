# 配管の交差のまたぎ

作成: 2026-11-13（日本時間）。状態: **実装済み（フロー図 段階1-E）**。計画は[目標のフロー図と現状の差分](../editor/flow-diagram-gap-2026-11-12.md#53-段階1-bf)の E。土台は[配管の分岐の点](line-junction.md)。

## 目的

つながっていない配管の交差を、系統図の慣習どおり半円のまたぎ（ジャンプ）で示し、[分岐の点](line-junction.md)（つながっている）と見分けられるようにする。画面ごとに、またがないか、弧でまたぐか、弧でまたいで下の線を切るかを選ぶ。

## 保存の形

- 画面（`screens[]`）に任意の `lineHops: "arc" | "cut"`（TypeScript は `LineHopStyle`）。`"arc"` は弧でまたぐ、`"cut"` は弧でまたぎ、下の線（またがれる線）を切る。省略はまたがない（既定）。`true`・`false`・その他の文字列は schema で拒否する（`"enum": ["arc", "cut"]`）。Symbol 定義には置けない（`symbols[]` の schema に無い）。
- 2026-11-13 の同じ PR の中で、`true`（入切）から形の文字列に改めた（切るか切らないかはエンドユーザーの好みなので選べるようにする、とのユーザー指示）。未リリースの属性なので `true` の読込・移行は作らない。
- schemaVersion は 0.37.0 を据え置く（任意属性の追加。Text の `format`・配置の `flipX` と同じ扱い）。リリース前なので旧形式の移行はない。
- 保存の `points` は変えない。またぎは描画時に計算する。
- 契約: `examples/line-hop-cases.json` を Rust（`line_hops_share_the_browser_contract`）と TypeScript（`line-hop.test.ts`）で共有する。Rust は Project を JSON の値のまま schema で検査するので、型の追加は無い。

## 編集

画面を選んでいないときの画面設定（「画面の背景色」の下）に「交差のまたぎ」の選択（「なし」「弧でまたぐ」「弧でまたぎ、下の線を切る」）を置く。「画面設定を適用」で背景色・名前・大きさと一緒に `update-screen` の 1 操作として適用し、元に戻す・やり直すで 1 操作ずつ戻る。「なし」にすると `lineHops` を消す（false を書かない）。コマンドの `lineHops` は形か `false`（消す）で、省略は変えない。

## またぐ条件

対象は[分岐の点](line-junction.md#対象)と同じ（同じ画面の、画面直下の表示中の Polyline。頂点 2 つ以上。回転・反転を適用した world 座標。Symbol 定義の中の線は対象外）。

2 本の線の線分が、互いの途中で**真に交差**するときにまたぐ。

- 平行・重なり（外積がほぼ 0）は交差としない。
- 交差点がどちらかの線分の端点（曲がり角を含む）から `junctionTolerance`（0.5）以内なら、接触（T 字・角の接触・継ぎ足し）とみなしてまたがない。
- 交差点が[分岐の点](line-junction.md)の円（半径＋0.5）の中にあるときもまたがない。点が「つながっている」ことを示すため。
- またぐ線の上（またぎの区間の近く）に分岐の点があるときは、半径を「点までの距離 − (点の半径＋0.5)」まで縮め、点の下の直線を残す。縮めた半径が最小の半分（2）未満ならまたがない。間に分岐の点があるまたぎ同士はまとめない（2026-11-13 Codex 指摘の修正）。
- 同じ線どうしの自己交差はまたがない。配管が自分と交わる図は少なく、どちらの区間を後とするかの規則がないため。

## どちらがまたぐか

**後に描かれる線**（`order` が大きい線）がまたぐ。先の線はそのまま直線で描き、後の線が上を越える見た目になる。重なり順と矛盾しない。

## 形

- 半径 `hopRadius` = またぐ線・またがれる線の太い方の線幅の 2 倍、最小 4。
- またぐ線分の上で、交差点の前後に半径の分だけ直線を描かず、半円の弧で結ぶ。
- **向き**: world 座標で画面の上（y が小さい側）へ膨らむ。垂直な線分（法線の y 成分が 1e-6 未満）だけは右（x が大きい側）へ膨らむ。線を描いた向き（頂点の順）にはよらない。斜めの線分も上の側。配置の回転・反転を適用した後の向きで決めるので、回転した配管でも見た目の規則は同じ。
- **またがれる線**: 画面の `lineHops` で選ぶ。切るか切らないかはエンドユーザーの好みによる（2026-11-13 ユーザー指示。それまでの「切らない」だけの判断を改めた）。
  - `"arc"`（弧でまたぐ）: 切らずにそのまま描き、半円の内側を通って弧の頂点で弧に触れる。電気・計装の系統図の慣習的なまたぎ（ホップ）と同じ見た目で、「弧のふくらみがある＝つながっていない」で見分ける。
  - `"cut"`（弧でまたぎ、下の線を切る）: 弧はそのまま描き、加えて、またがれる線を交差点を中心とする半径 R の円の中だけ描かない。またがれる線は交差点を通るので、切る区間は線分の上の交差点から ±R で、交差の角度によらない。
  - **R = 弧の半径 ＋ またぐ線の線幅/2 ＋ 余白（またがれる線の線幅）**。弧は交差点を中心とする円なので、またがれる線は交差点から弧の半径の所で弧の中心線に出会い、線幅/2 の所で弧の線の外側を出る（線に沿う向きが円の半径の向きなので角度によらない）。余白は、またがれる線の端の形が丸（実線は丸い端、`lineCap`）で端が線幅/2 伸びる分と、見える隙間の線幅/2 の和。たとえば線幅 2 どうしで半径 4 なら R = 4 ＋ 1 ＋ 2 = 7。端が平らな破線では、見える隙間が線幅の分になる。
  - まとめた弧（「近いときの扱い」）では、交差点が弧の中心にないので、またがれる線に沿って交差点から弧の円までの距離（遠い側）を弧の半径の代わりに使う。まとめた弧の下でも、またがれる線が弧と重ならない。
  - 切る区間は線分の端で止める（曲がり角をまたいで続く区間は作らない）。
  - 切る区間が、またがれる線の上の[分岐の点](line-junction.md)の円（半径＋0.5）にかかるときは、その交差では切らない（弧だけ描く）。点の下の線が消えて枝が浮くのを防ぐ（弧の半径を縮める `blocked` と同じ計算）。
  - 切る区間が、またがれる線のその線分自身のまたぎの弧に重なるときも切らない（弧を消さないため）。
  - 同じ線分の上で重なる、または間の直線が最小半径（4）より短い切る区間は 1 つにまとめる（間に分岐の点・弧があるときはまとめない）。
  - 弧を省略した交差（線分の端に近い・分岐の点で縮めて小さすぎる・分岐の点の円の中）では切らない。
  - マスクは使わず、パスを途切れさせる。背景画像・小窓・埋め込みの画面で、背景の色によらず同じ結果にするため（それまで切らなかった理由の「隙間の色を決められない」は、マスクや背景色の上塗りでなくパスを途切れさせることで解消する）。

## 近いときの扱い

- **線分の端の近く**: 半径を交差点から線分の両端までの距離に縮める。縮めた半径が最小の半分（2）未満なら、またがずに交差のまま描く。弧が曲がり角を越えないため。
- **またぎ同士が近い**: 同じ線分の上で区間が重なるか、間の直線が最小半径（4）より短くなるときは、まとめて 1 つの半円（区間の両端を結ぶ、半径は区間の半分）にする。弧が重なって乱れないため。
- 別の線分（曲がり角をはさむ）のまたぎはまとめない。

## 描画の置き換え

- `line-hop.ts` の `screenHopPaths(objects, style)` が、またぎ（`"cut"` では切る区間も）のある Polyline の id ごとに SVG パス（`M`・`L`・`A`）を返す。区間（`HopSpan`）は線分の始点からの距離で、弧のほかに `kind: "gap"`（切る区間）があり、`hopPath` は切る区間を `L 始点 M 終点` で途切れさせる。
- パスは配置の**ローカル座標**で作る。各配置は `objectTransform`（平行移動・回転・反転）の `<g>` の中で描くため。回転・反転は長さを変えないので、world で求めた線分の上の距離をローカルの線分にそのまま使える。弧の回る向き（sweep）は、world で決めた頂点を `worldToObject` でローカルへ戻して求める（反転で回り方が逆になっても、見た目の向きは保たれる）。
- `Primitive.svelte` は `hopPath` があれば `<polyline>` の代わりに `<path data-line-hop>` を描く。線色・線幅・線種（破線・点線の `stroke-dasharray`）・端の形・角の丸めは polyline と同じ属性。矢印は保存の `points` から求めるので変わらない（端点はまたがないため矛盾しない）。切る区間で途切れた後の破線・点線の模様は、SVG の規則どおり途切れた先（次の部分パス）から始め直す。
- `Renderer`（Designer の編集・表示プレビュー。Symbol 定義の編集では計算しない。ドラッグ中は分岐の点と同じ `draggedObject()` の位置で計算する）、`ScreenPainting`（画面の小窓）、`ScreenView`（埋め込みの画面）が同じ関数を使い、`ObjectPainting` を通して渡す。

## 選択・hit・外接矩形

またぎは描画だけで、選択・hit・外接矩形（`getLayoutBounds`）・整列・接続点には含めない。分岐の点と同じく、他の配置の組合せで現れたり消えたりするため。はみ出しは線から半径（線幅の 2 倍、最小 4）まで。

## 性能

- `$derived` で、画面の配置（またはドラッグのプレビュー）か `lineHops` が変わったときだけ計算する。またがない（省略）ときは計算しない。`"cut"` の切る区間は、弧を置いた交差だけから求めるので、調べる線分の数は増えない。読取の更新では計算しない。
- `SegmentIndex`（線分の格子）に入れ、線分ごとに `alongSegment(a, b)` で、その線分が通る格子（`segmentCells`。外接矩形の全格子ではない）の線分だけを調べる。全組合せの O(n²) にしない。分岐の点も格子に入れ、交差点の格子の点だけと比べる。1000 本（500 個の十字、交差 500）の試験は、時間ではなく線分ごとに調べる候補の線分の数（10 以下）で確かめる（CI の負荷で揺れないため）。長い配管が格子状に多数交わる極端な図（500×500 本で 25 万の交差）では秒単位になり得るが、またぎの数に比例する。
