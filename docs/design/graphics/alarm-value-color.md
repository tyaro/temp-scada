# 数値の文字色を警報の状態で変える（alarmColor）

作成: 2026-11-20（日本時間）。状態: **設計（未実装）**。起票は Issue #304。Issue の決めること 6 点のうち、案（1）と見た目・範囲の 4 点は 2026-11-20 にユーザーが推奨案を選んだ（下表）。同日、Fable の通しレビュー（P1 4 件・P2 11 件・P3 7 件）を反映した。基準は[段階3の警報設計](../runtime/alarm-stage3-design.md)の §7「表示」と[警報の小札](alarm-badge.md)。

## 目的

監視画面では、警報中の計器値は数値そのものの色が変わる。運転員は小札を探さずに、数値の色で異常に気づく。今は、しきい値の警報を示すには数値の隣に小札（`alarmBadge`）を置くしかなく、計器が多い画面では数値 1 つにつき小札が 1〜4 個増える。数値の Text が警報の定義を指し、その状態で文字色を変えられるようにする。

参照にした実プラントの画面は、リポジトリにも文書にも載せない（画像・配置・名称を書かない）。

## 保存契約

```ts
// タグを結合した Text の shape に任意で足す
alarmColor?: { alarmId: string }; // alarms.definitions[].id
```

- schema（Text の枝）: `dependentRequired: { alarmColor: ["binding"] }`（タグの結合が要る）と、今の排他の `not.anyOf` に `["alarmColor", "boolDisplay"]` を足す。`slotBinding`・`equipmentProperty`・`stateColors` は `binding` との既存の排他で落ちる。
- `$defs/primitive` は画面と Symbol 定義で共用なので、Symbol 定義の中は schema では区別しない。Symbol 定義の中の Text は `binding` を持てない今の検査（TS `project.ts` の「Symbol 定義内の直接タグ割り当てには対応していません」、Rust `crates/scada-model/src/lib.rs` の同じ検査）で拒まれ、`alarmColor` はその `binding` を必須とするので一緒に拒まれる。
- `alarmColor` の中は `alarmId` だけ。`additionalProperties: false`、`alarmColor: null` は拒否（省くことで「無し」を表す）。`format` とは一緒に持てる。
- 検査（TS は `parseProject` 経由、Rust は `crates/scada-model/src/alarms.rs` の `validate_badges` と同じ画面のループ）: 指す定義が無ければ「数値の警報の色が指す警報の定義が見つかりません」。TS と Rust で同じ文字列にする。定義のタグと結合のタグの一致、定義の種類・限界・`enabled` は問わない（無効の定義も指せる）。
- 結合しているタグの型（数値か）は保存では確かめない（タグ一覧は Project に無い）。

## 編集コマンド

- `update` の `alarmColor`（`null` は削除。同じ値は no-op、1 確定 1 Undo）。Symbol 定義の編集中（`definitionId` がある）は拒否する（`format` の更新と同じ）。
- タグの結合を外す（`binding: null`）と、同じコマンドで `alarmColor` も消す（同じ Undo、`format` と同じ）。`binding: null` と `alarmColor` の設定を同じ patch で送ったら拒否する（`format` と同じ）。
- `alarmColor` を持つ Text に `boolDisplay` を付ける更新は拒否する（先に警報の色を外す）。`boolDisplay` を持つ Text に `alarmColor` を付ける更新も拒否する。自動では消さない。

## 参照の保護と clipboard

小札の関数は限界の必須を検査する（`alarm-badge.ts` の `validateAlarmBadgeTarget`）ので、`alarmColor` には流用しない。「定義の id があるか」だけを見る `validateAlarmColorTarget`・`assertAlarmColorPasteTarget` を別に作り、利用者を集める処理だけを共通にする。

- 使用中の定義の削除: 編集コマンドは `parseProject` で拒否される。警報の設定（`editor/alarm-handler.ts`）の使用中の表示は、小札と `alarmColor` を持つ Text を 1 つの一覧に集めて「この警報は使用中です：画面 1／警報の小札、画面 1／数値の文字。先に小札・数値の文字から外すか、指す警報を変えてください。」のように出す。各項目は今の小札と同じく「画面の名前／配置の名前」で、配置の名前が無ければ「警報の小札」「数値の文字」。並びは画面の順、配置の順。5 件までを挙げ、残りは「ほか」（今の小札の表示と同じ）。種類・限界の変更で壊れるのは小札だけなので、そのときは今の小札の文言のまま出す。
- 種類・限界・タグの変更: 小札が指している限界を外す・bit へ変える更新は従来どおり拒否する。`alarmColor` だけが指している定義は、種類・限界・タグを変えてもよい。
- clipboard（`clipboard.ts`）: コピー・切り取りで添える定義の集合（今の `badgeAlarmIds`）を「選んだ小札 ∪ `alarmColor` を持つ Text が指す id」にする（同じ定義は 1 件）。`parseClipboard` は、どれにも指されない定義を今と同じく拒む。
- 貼り付け（`editor/paste-handler.ts`）: 定義を取り込まず、貼付け先の**同じ id** の定義を指す。無ければ「貼り付け先の Project に、数値の文字が指す警報「T-01 温度」の定義がありません。…」で貼り付け全体を拒む。埋込画面と一緒に取り込む画面の中の Text（`importedObjects`）も同じく確かめる。Symbol 定義への貼り付けは、タグを結合した Text を拒む今の検査で落ちる。

## 状態の合成

純関数 `alarm-value-color.ts` が、指す定義の condition の表示状態（`alarm-view.ts` の `alarmConditionView`）から、**色の値ではなく意味**（`tone`: `normal`・`severity`・`unknown`、その severity、下線の有無と severity、点滅の有無、`<title>` の文字）を返す。意味から色への写像は見た目の側に置く。

### 見る condition

- 編集中の定義から出る condition（しきい値なら定義にある限界ごとの `${alarmId}:${limit}`、bit なら `alarmId`）と、snapshot の `engine.conditions` にある `alarmId`・`${alarmId}:hh`・`:h`・`:l`・`:ll` の**和集合**。snapshot 側は編集中の定義の種類に関係なく 5 つとも見る。
  - 編集で限界を外して未適用のあいだも、Engine で発生中の限界を見落とさない。
  - 種類を変えて未適用のあいだ（しきい値 → bit、bit → しきい値）も、host は前に適用した定義のまま評価しているので、その condition の状態を出す。編集中の定義から出る新しい condition は未適用なので不明になり、発生中が無ければ灰色、あれば発生中の色になる（上の規則のとおり）。
- 指す定義が編集中の Project に無いことは保存の検査で起きない。

### severity と優先

- severity は小札と同じく適用中の表示情報（`applied.displays[condition id].severity`）から取り、無ければ **high** とする（小札の地の色と揃える。同じ condition を指す小札と文字の色がずれない）。
- 優先の順: severity（high → medium → low）、同じなら限界の外側（`hh` → `ll` → `h` → `l`）、限界の無い bit の condition（`alarmId`）は同じ severity の限界の後。

### 規則

| 決めるもの | 規則                                                                                                                                                                                               |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文字色     | 発生中（未確認・確認済み）の condition があれば、その中で優先の最も高いものの severity の色。無く、どれかが不明（`unknown`）か評価不能（`unavailable`）なら**不明の灰色**。それ以外は配置の `fill` |
| 下線       | 未確認（発生中・復帰）の condition があれば、その中で優先の最も高いものの severity の色で下線を引く。無ければ引かない（文字色とは別に決める）                                                      |
| 点滅       | Project の `alarms.blinkUnacked` が真で、下線を引くときだけ。**下線だけ**を点滅させ、文字は薄くしない                                                                                              |

規則から出る組合せの例（単体試験で固定する）:

| condition の状態                                               | 文字色                     | 下線                               |
| -------------------------------------------------------------- | -------------------------- | ---------------------------------- |
| すべて正常                                                     | `fill`                     | なし                               |
| H 発生中・確認済み、HH 発生中・未確認                          | HH の severity             | HH の severity                     |
| H 発生中・確認済み、HH 復帰・未確認                            | H の severity              | HH の severity                     |
| HH 復帰・未確認、ほかは正常                                    | `fill`                     | HH の severity                     |
| HH 復帰・未確認、追加した L が未適用（不明）                   | 不明の灰色                 | HH の severity                     |
| 編集で外した HH が Engine で発生中、H は正常                   | HH の severity             | HH が未確認なら                    |
| しきい値 → bit へ変えて未適用、Engine の HH が発生中・未確認   | HH の severity             | HH の severity                     |
| bit → しきい値へ変えて未適用、Engine の bit が発生中・確認済み | bit の severity            | なし                               |
| しきい値 → bit へ変えて未適用、Engine の限界はすべて正常       | 不明の灰色（bit が未適用） | なし                               |
| 追加した LL だけが未適用、ほかは正常                           | 不明の灰色                 | なし                               |
| H 発生中で condition 単位の評価不能が重なる                    | H の severity              | 未確認ならあり                     |
| snapshot が無い・Engine が止まっている・別の Project           | 不明の灰色                 | なし                               |
| `ackMode: none` の H が発生中                                  | H の severity              | なし（確認不要は未確認にならない） |

- 発生中に評価不能が重なっても発生中の色のままにする（発生中を隠さない）。小札の「?」の印に当たるものは数値には付けず、`<title>` の文字だけで示す（既知の制約）。
- 不明の灰色は、Engine が無い・動いていない・Engine 単位の評価不能・別の Project・未適用のどれでも同じ。無効（`enabled: false`）の定義は host が condition を作らないので、いつも未適用で灰色になる（`<title>` は「この警報は適用されていません」）。ブラウザ版の Designer とデモ（Engine が無い）では、`alarmColor` を持つ数値はいつもこの灰色になる。
- 数値と単位はいつもどおり読取の値を出す。値が欠測（`-- · 理由`）のときも同じ規則で色を付ける（警報の状態は値の表示と独立）。SIM の値は警報の評価と無関係なので、値と色が食い違うことがある（既知の制約）。
- 色は配置の `colorAlpha`・`opacity` をそのまま使う（不透明度は変えない）。

## 見た目

色は部品で固定し、Project では変えない。

| 状態        | 明るい背景 | 暗い背景  |
| ----------- | ---------- | --------- |
| severity 高 | `#dc2626`  | `#f87171` |
| severity 中 | `#c2410c`  | `#fb923c` |
| severity 低 | `#a16207`  | `#facc15` |
| 不明の灰色  | `#6b7280`  | `#9ca3af` |

- 組は、その Text を描く画面の背景色（`screen.background`）とのコントラスト比（WCAG の相対輝度）で、色ごとに比の高い方の組を選ぶ。`canvas-colors.ts` の輝度の閾値（150）は使わない（中間色の背景で比が 1.1 まで落ちる。例: `#969696` 上の `#f87171`）。比の計算は `canvas-colors.ts` などに関数を置いて共用する。背景を知る 3 つの描画の経路（編集とミニマップの `Renderer.svelte`、プレビュー・運転表示の `ScreenPainting.svelte`、埋込画面の `ScreenView.svelte`）から、`ObjectPainting` → `Primitive` → `TextPrimitive` へ組を渡す。埋込画面の中では、埋め込まれた画面の背景で選ぶ。
- 選んだ色でも背景との比が 4.5 に届かないとき（灰の背景ではおよそ `#404040`〜`#c0c0c0`。両方の組が届かない）は、**暗い組の色に黒（`#000000`）の縁取り**を付ける。縁取りは文字の外側だけに描き（SVG の `paint-order: stroke`、太さ `max(1, fontSize × 0.12)`）、文字の塗りを削らない。暗い組の 4 色は黒に対して 7.59 以上なので、縁取りの中で読め、縁取りが中間色の背景から文字を切り離す。下線にも同じ太さの黒の縁を付ける。
- どの色も、白（`#ffffff`）・既定の暗い背景（`#0b1220`）に対して文字のコントラスト比 4.5 以上。縁取りのときは文字と縁の比が 7.59 以上（写像・比・縁取りの境目の単体試験は V2）。
- 下線: 結合した Text はいつも 1 行（`TextPrimitive`）なので、1 本だけ引く。位置は計測の `baseline` から `fontSize × 0.15` 下、太さは `max(1, fontSize × 0.08)`（画面の単位）、幅と左端は計測の `left`・`inkWidth`。Text の枠（`overflow="hidden"`）の内側に収まる位置で、回転・揃えは文字と同じ変換に乗る。表示が `###`（はみ出し）のときもその文字の幅で引く。
- 点滅: 小札と同じ動き（opacity 0.35 の 1 秒の steps）を**下線だけ**に当てる。文字には当てない（白い背景の high は opacity 0.35 で比が 1.76 まで落ちる。数値はいつも読めるようにする）。`prefers-reduced-motion: reduce` では止め、下線を出したままにする。
- 色だけに頼らないよう、Text の説明（`aria-label`・`<title>`。今は値の説明と共用）の後ろに警報の状態の文字を足す。形は「警報 T-01 温度: HH 未確認（発生中）、H 発生中」のように、正常でない condition を優先の順に「限界名 状態」で並べ、全部が正常なら「警報 T-01 温度: 正常」、不明なら「警報 T-01 温度: 不明（警報の Engine が動いていません）」。評価不能の重なりは「H 発生中・評価不能」（`alarmViewText` と同じ「・」で、限界名は状態の前に置く）。
- e2e 用に、Text の要素へ `data-alarm-tone`（`normal`・`high`・`medium`・`low`・`unknown`）と `data-alarm-underline`（severity、無ければ付けない）を付ける。

## 編集（Inspector）

- 数値の書式と同じく、独立した「警報の色」フォーム（`designer/AlarmValueColor.svelte`、適用は「警報の色を適用」、未適用の保護と一括の事前検証は他のフォームと同じ仕組み）。
- 出す条件: タグを結合した画面直下の Text で、`boolDisplay` を持たないもの。タグの型は問わない（タグ一覧が無い Project でも出す）。すでに `alarmColor` を持つ Text には、解除のためにいつも出す。
- select は「使わない」と定義の一覧。結合しているタグと同じタグの定義を先に、ほかのタグの定義を後に、見出し（optgroup）を分けて並べる。無効の定義は名前に「（無効）」を付ける。Project に定義が無いときは select を無効にし「警報の定義がありません」と出す。
- 編集・プレビュー・運転表示のどこで描いても、小札と同じ `alarm-view-state.svelte.ts` の状態を読む。

## 受入

- 画面直下の数値の Text が、指した警報の定義の状態で文字色を変える。正常・発生中（未確認・確認済み）・復帰・未確認が、同じ condition を指す小札と矛盾しない（severity が表示情報に無いときも含めて、並べた e2e）（V2）。
- 合成の単体試験（V1）: 上の組合せの例の表の全行（種類の変更の両方向を含む）、bit の定義（condition id は `alarmId`）、severity が表示情報に無い（high）、H と HH の severity が逆転した定義（severity が先）、無効の定義（灰色）。
- 警報の状態が不明・評価不能のとき、数値を正常の色や直前の色で出さず、不明の灰色で出す。発生中に評価不能が重なったら発生中の色のまま（V1・V2）。
- `blinkUnacked` のときだけ未確認で下線が点滅し、文字は点滅中も薄くならない。「動きを減らす」では止まって下線を出したままになる（V2）。
- 描画（V2）: 明るい背景・暗い背景・中間色の背景（比 4.5 の境目の両側、縁取りの出入り）、背景の違う埋込画面で組と縁取りが切り替わる。点滅中の文字の色と不透明度が変わらない。プレビュー・運転表示・ミニマップでも同じ組。`###` のときの下線、回転した Text の下線。
- 編集（V1）: `alarmColor` の設定・削除・同じ値の no-op・Undo、`binding: null` で消えて Undo で戻る、`binding: null` と `alarmColor` の同時の拒否、`boolDisplay` との両方向の拒否、Symbol 定義の中での拒否。
- 削除の拒否（V1）: 小札と Text の両方が指す定義の削除で、両方が使用中として挙がる。種類の変更は小札があれば拒否、Text だけなら通る。限界の削除も同じ。
- clipboard（V1）: 限界を持たない `alarmColor` の Text のコピー・切り取り・貼り付けが通り、同じ id の定義へつながる。小札と Text が同じ定義を指すコピーでは定義が 1 件。どれにも指されない定義を含む clipboard の拒否。定義の無い Project への貼り付けは全体が拒否される（埋込画面と一緒に取り込む画面の中の Text を含む）。
- Rust と TypeScript が同じ契約ケースを通る（V1）。
  - 受け入れ: しきい値の定義を指す Text、bit の定義を指す Text、無効の定義を指す Text、結合のタグと違うタグの定義を指す Text、`format` と一緒の Text。
  - 拒否: 無い定義、`alarmColor: null`、`alarmId` の欠落・未知の項目、`binding` の無い Text（静的・機器情報・`slotBinding`）、`boolDisplay` と一緒の Text、Symbol 定義の中の Text（`binding` の検査の文言）、Text 以外の図形への `alarmColor`。

## 既知の制約・後続

- 組と縁取りは画面の背景で選ぶので、数値の後ろに図形の塗りを敷いた配置（暗い画面に白い値の箱など）や背景画像の上では読みにくい色になることがある（暗い組の `#facc15` は白に対して約 1.5）。値の箱を敷く画面が目標の画面に多ければ、Text ごとに組を選ぶ項目か、後ろの塗りからの判定を後続で考える。
- 配置の `fill` を灰色にすると、不明の灰色と見分けにくい。明るい組の high（`#dc2626`）と medium（`#c2410c`）は近い色なので、`<title>` の文字で補う。
- 表のセル、Symbol 定義の中の Text（機器のタグから警報の定義を引く仕組みが要る。警報設計 §8）。
- 背景（文字の後ろの塗り）の色を変えること、液位の色、色の Project ごとの変更。
- Tauri 実機（実 Engine の snapshot）での見た目。
