## 2 つの軸

- 配置・運用フェーズ: 開発 / 初期設定と運用。ユーザー管理を必須にするかを決める。
- アプリの起動 mode: Editor / Runtime。編集機能を持つかを決める（上流設計 §18）。

現在の「編集 / 表示プレビュー」は描画と操作の確認用 UI であり、運用フェーズや正式な起動 mode・認証境界を切り替えるものではない。

## 操作の扱い

| フェーズ / 状態    | 監視画面の閲覧 | Project / 設定変更・ユーザー管理 | 設備操作・書込み・警報 ACK 等                    |
| ------------------ | -------------- | -------------------------------- | ------------------------------------------------ |
| 開発・初期設定     | ログイン不要   | ローカル開発・設定はログイン不要 | 実機操作の接続は別途実装・検証。現段階では未対応 |
| 運用・未ログイン   | 閲覧専用で許可 | 不可                             | 不可                                             |
| 運用・ログイン済み | 許可           | 各操作に必要な権限を持つ場合のみ | 各操作に必要な権限を持つ場合のみ                 |

警報の ACK とブザー停止は、設備への書込みではなく SCADA の警報 Engine の操作である。扱いは[段階3 警報の設計](alarm-stage3-design.md)§6 に従う（開発・初期設定ではログイン不要、運用ではログイン済みの Admin だけ、ブザー停止は権限不要）。

「運用時のユーザー管理必須」は、閲覧開始のたびにログインを要求する意味ではない。運用への移行時に管理者アカウントの作成・保存を済ませ、設定変更や設備操作時に認証・認可を要求する。具体的な役割と権限セットは後続設計で決める。

## 運用への移行と再起動

- 運用への移行は、管理者と必要な永続設定が作成済みであることをバックエンドで確認してから確定する。ブラウザの保存値だけで運用移行や権限付与を決めない。
- 再起動後は、配布・保存済み Project の監視画面を閲覧専用で開く。管理者の認証情報を保存して自動ログインする方式にはしない。
- 未ログインの監視から必要なときだけログインし、権限のある操作へ進む。ログアウト後は監視を続けられる。
- ユーザー DB や認証サービスが利用できないときに、初期設定へ自動で戻したり、無認証の編集・書込みを許可したりしない。操作は拒否し、閲覧可能かは監視データの取得経路と接続状態で判断する。
- 運用から初期設定へ戻す正式な手順は後続で設計する。未ログイン利用者が UI の切替だけで戻せる形にはしない。
- 匿名閲覧を許可する接続範囲（この端末 / LAN）は別途決める。現行の開発サーバーは loopback のみで待ち受ける。

## Banto と Hub との境界

Banto の認証・ユーザー管理・セッション管理の既存 API と backend を確認し、SCADA の host に接続する。権限は UI の非表示だけに頼らず、Rust domain / API 側で検証する。閲覧専用の監視へ管理者権限を持つ Hub の資格情報を渡さない。PLC 操作は引き続き Hub の書込み経路・認可を通す。

この方針の匿名監視は、開発エディタが現在出している「表示プレビュー」とは異なる。現在は保存済み Project の自動再開、実データ監視、運用移行、ログイン画面、ユーザー管理はまだ提供しない。
