# 警報の端末設定

状態: **設計案（未承認・未実装）**。2026-11-17 作成。[段階3 警報の設計](alarm-stage3-design.md)の後続で、§5.3 の保持の上限、§4.5 の読み直しの値、§5.5 の `alarm_settings_get`／`alarm_settings_set`、§6 の音のファイルを、端末（host）の設定として保存・変更できるようにする。

## 1. 現状（2026-11-17 の `work`）

- 端末設定 `alarm-terminal.json`（`crates/scada-host/src/alarm_terminal.rs`、version 1）は、監視中の Project・切替中の記録・session の世代番号だけを持つ。
- 保持の上限による古いイベントの削除は**作っていない**。警報 DB の `event` 表は増え続ける。
- 読み直しの値（周期 10 秒・期限 5 秒・連続失敗の期限 30 秒・張り直しの連続失敗 3 回）は `alarm_runtime/freshness.rs` の既定値で固定。runtime には値を受け取る `AlarmRuntime::start_with_config` があるが、service は既定値の `start` を呼ぶ。
- ブザーはコードで作ったビープ（`'static` の buffer を `PlaySoundW` の `SND_MEMORY | SND_ASYNC` で鳴らす）だけで、音は変えられない。`BuzzerPlayer` は音を選ぶ口を持たない。
- `alarm_settings_get`／`alarm_settings_set` と設定の画面は無い。

## 2. 持つ値

端末設定に `alarm` の欄（`#[serde(default)]`）を足し、次を持つ。欄が無い（既存の端末）ときは既定値で読む。リリース前なので、新しい形を古い版で読めることは保証しない。端末設定は `deny_unknown_fields` なので、新しい形のファイルを古い build で開くと `Corrupt` で監視が止まる（開発中に branch を行き来すると起きる）。

| 値                                            | 既定                      | 範囲                                        |
| --------------------------------------------- | ------------------------- | ------------------------------------------- |
| 保持の上限の種類 `retention.kind`             | `days`                    | `days`（日数）か `count`（件数）            |
| 保持の日数 `retention.days`                   | 365                       | 1〜3650                                     |
| 保持の件数 `retention.count`                  | 1,000,000                 | 10,000〜10,000,000                          |
| 読み直しの周期 `reread.intervalSec`           | 10                        | 2〜300                                      |
| 1 回の期限 `reread.timeoutSec`                | 5                         | 1〜周期                                     |
| 連続失敗の期限 `reread.failureLimitSec`       | 30                        | 周期の 2 倍〜3600                           |
| 張り直しの連続失敗 `reread.reconnectFailures` | 3                         | 1〜10                                       |
| 音 `sound`                                    | `default`（同梱のビープ） | `default` か `custom`（取り込んだファイル） |

- 範囲と相互の関係（期限 ≤ 周期、連続失敗の期限 ≥ 周期の 2 倍）は host が検査し、外れたら保存しない。画面も同じ規則で先に示す。
- 種類を切り替えても、使わない方の値は残す（戻したときに入れ直さなくてよい）。
- 読込み時に `alarm` 欄の値が範囲や相互の関係を外れていたら（手で編集した場合など）、関係する組ごとに既定値に戻して読む。読み直しの4つの値は互いに関係するので、どれか1つでも範囲か関係を外れたら4つとも既定値にする（1つだけ戻すと、周期 2 秒に期限の既定 5 秒が並ぶように関係を外れうる）。保持は種類・日数・件数をそれぞれ独立に戻し、音は §5 の検査に通らなければ既定にする。戻したら`alarm_settings_get` に警告を出す。`Corrupt` にはしない（設定の値の誤りで監視を止めない）。JSON として読めない・型が違うときは従来どおり `Corrupt`。
- 期限を周期と同じにすると、送信中は次の回を飛ばすので、期限切れが続く間の実質の周期は 2 倍になる。失敗の判定は最初の失敗からの経過で行うので、連続失敗の期限の意味は変わらない。

## 3. 保持の上限による削除

- 対象は監視中の Project の警報 DB の `event` 表だけ。監視していない Project の DB は、次にその Project を監視したときに同じ規則で消す。`session`・`last_state`・適用済みの定義の表は消さない（段階3 §5.3）。
- 残すイベント（削除の対象から外す）:
  - その DB の最新のイベント（段階3 §5.4 の「状態不明の期間」の始まりは、前の session の最大通番のイベントから求める）。
  - `last_state` にある各 condition の、display を持つ最新のイベント（削除・無効化・接続先変更の終端で、表示情報を写す元）。
  - 発生のイベントは残す対象にしない。長く続く回は、発生のイベントが消えて ACK などだけが残ることがある。いまの一覧の発生時刻は `last_state` の `occurredAt` で出すので困らない。表示情報を写す元も消えた場合は、段階3 §5.3 のとおり `display: null` で終端を書く。
- 消し方: 通番の小さい順（主キーの走査）に見て、残すイベントは飛ばし、期限を超えていないイベントに当たったらそこで止める。履歴の途中に穴を開けず、古い端が進むだけにする。
  - 日数: `at_ms` が「いまの壁時計 − 日数」より古いものが期限を超えたもの。壁時計が戻っていた期間のイベントが先頭にあると、その時刻が期限を過ぎるまで止まる（それより新しい通番も消えない）。
  - 件数: 「最大の通番 − 件数」以下の通番が期限を超えたもの（AUTOINCREMENT で通番を使い回さないので、`COUNT(*)` で走査せずに近似で足りる。残すイベントの分だけ件数を超えることがある）。
- 1 回に消すのは 10,000 件まで。上限まで消した回は、残りがある間は 5 秒あけて次の回を続ける。残りが無くなったら 1 時間ごとに戻る。pool は接続 1 本なので、1 回の transaction を小さく保ち、Engine の書込みを長く待たせない。
- 実行の時機: session を始めた後、その後は上の間隔で。評価の処理列に入れて行う（評価と別の書込み経路を作らない）。設定を変えたら、次の回を待たずに一度実行する。Engine が動いていない（未適用・停止中）ときは何もせず、次に session を始めたときに行う。
- 削除の transaction でも、イベントの追記と同じく session の所有を確かめる（`require_session`）。所有が変わった DB を古い Engine が消さない。
- 履歴に書けない間（段階3 §5.3 の書込みの失敗中）は削除を試さない。
- 削除の失敗の扱いは段階3 §5.3 の分類に従う: 一時的な失敗（BUSY・LOCKED・I/O など）は書込みの失敗に数えず、評価・ACK・適用を止めない。ログに残し、次の回に試す。破損・schema の不整合・session の不一致は、イベントの書込みと同じく Engine を止める。
- 削除はイベントとして記録しない（履歴の古い端が進むだけ）。SQLite は消した分の page を再利用するので、ファイルの大きさは縮まないが増えるのが止まる（VACUUM はしない）。

## 4. 読み直しの値の反映

- 保存した値は、動いている Engine にすぐ反映する。runtime の制御に設定の差し替えを足し、次の読み直しを「いま＋新しい周期」に置き直して、可用性の判定を一度やり直す。失敗の始まりと張り直しの回数はそのまま使う（判定は最初の失敗からの経過と回数で比べるだけなので、状態の作り直しは要らない）。新しい連続失敗の期限・回数をすでに超えていれば、その判定で受信の途絶になる。
- Engine が動いていないときは保存だけし、次に session を始めたとき（`start_with_config`）から使う。

## 5. 音のファイル

- 選べるのは WAV だけ（再生に使う Windows の `PlaySoundW` が WAV しか鳴らせないため）。host が取込みのときに中身を検査し、次の形だけ受け入れる: RIFF/WAVE、fmt の形式が PCM（1）、8 bit か 16 bit、1〜2 ch、chunk の大きさがファイルの範囲に収まる、data chunk がある。`WAVE_FORMAT_EXTENSIBLE`・24 bit 以上・圧縮形式は拒否する。大きさは 1 MB まで、長さは 5 秒まで（繰り返し鳴らす音なので短くする）。
- host が自分のダイアログでファイルを選び、検査してから `%LOCALAPPDATA%\temp-scada\alarm-sound.wav`（`local_data_dir()` の下）へ一時ファイルからの置換で写す。元のファイルを動かしたり消したりしても鳴る。webview はパスを持たない（3-C1 の `fileId` と同じ考え）。
- 設定の `sound` には `default` か `custom` と、取り込んだファイルの元の名前（表示用）・大きさ・hash を持つ。
- 順番: 取込みは、ファイルを置いてから設定を保存する。既定に戻すは、設定を保存してからファイルを消す。どちらも途中で止まっても、設定の hash とファイルが合わなければ既定のビープで鳴らす。
- 読込み: host は起動時と取込み・既定に戻すのときに、ファイルを読んで hash と上の検査を行い、鳴らす音（取り込んだ音か既定のビープ）を決める。`PlaySoundW` の `SND_ASYNC` は再生の成否を確実には返さないので、鳴らすときの戻り値で代替を決めない。読めない・hash が合わない・検査に通らないときは既定のビープにし、理由を残す。
- 再生の経路: `BuzzerPlayer` に音を差し替える口（`set_sound`）を足し、scada-host が決めた音の bytes を Tauri 側の player に渡す。player は buffer を自分で持ち、鳴っている最中に差し替えるときは、先に止めてから buffer を替え、ブザーの状態（`ringing` なら繰り返し）に従って鳴らし直す。
- 画面への状態: `alarm_snapshot` に並びの欄 `buzzerSound`（`kind: default|custom`、`fallback`: 代替にした理由か null）を足す。`buzzer` の文字列の enum は変えない。変化は既存の `alarm_changed_lagged` で取り直させる。代替のときは、ヘッダーと一覧の窓に「設定の音を鳴らせないため、既定の音で鳴らしています」と示す。
- 「既定に戻す」で `default` にし、取り込んだファイルを消す。
- 「試しに鳴らす」（`alarm_sound_test`）:
  - いまの設定の音を一度だけ鳴らす。警報の状態・ブザーの状態は変えない。
  - ブザーの状態の排他の下で行い、ブザーが `ringing` のときは拒否する（`PlaySoundW` は process で 1 音だけなので、試しの音が警報の繰り返しを置き換えて止めてしまうため）。画面で押せなくするだけでなく host で拒む。
  - 試しの最中に警報の音（繰り返し・一度鳴らし）が来たら、警報の音が置き換える（警報を優先）。
  - 押し直すと頭から鳴る（`PlaySoundW` が前の再生を置き換えるので重ならない）。host は非同期の再生の終わりを知らないので、「鳴っている最中は押せない」とはしない。長さは 5 秒までなので、止める操作は設けない（`alarm_buzzer_silence` でも止まる）。

## 6. IPC と権限

| command              | 内容                                                                                                                                                                                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `alarm_settings_get` | §2 の値、読込み時の警告、保持の現況（DB のイベント件数・残すイベントを除いた最も古いイベントの時刻）、音の表示情報を返す。保持の現況は `alarm_history` と同じく別の接続で読む。監視中の Project が無いときは現況を null にする。権限は要らない。 |
| `alarm_settings_set` | 保持・読み直しの値を保存する。音は含めない。                                                                                                                                                                                                     |
| `alarm_sound_import` | host のダイアログで WAV を選び、検査して取り込む。取り消しは変更なし。                                                                                                                                                                           |
| `alarm_sound_reset`  | 音を既定に戻す。                                                                                                                                                                                                                                 |
| `alarm_sound_test`   | いまの設定の音を一度鳴らす（§5）。権限は要らない。                                                                                                                                                                                               |

- 変更（`set`・`import`・`reset`）の権限は保存と同じ扱い: 開発・初期設定ではログイン不要、運用ではログイン済みの Admin だけ（[アクセス方針](access-policy.md)の「Project / 設定変更」）。`authorize_alarm_ack` と同じ `require_role(Role::Admin, …)` の形で `authorize_alarm_settings` を足し、ACK と同じフェーズの検査（`verify_alarm_phase`）を通す。
- 端末設定の書込みは、世代番号の書込みと同じ process 内の排他（`AlarmTerminal` の `Mutex<Settings>`）の下で、ファイル全体の置換（`save()`）で行う。同期の永続書込みなので、IPC からは blocking の thread で呼ぶ。
- 端末設定を開けないとき（`terminalUnavailable`）は、get は理由を返し、set・import・reset は拒否する。試しに鳴らすは既定のビープで行う。
- 保存したら `alarm_changed_lagged` で画面に snapshot を取り直させる。

## 7. 画面

- 入口: メニューの「ファイル」→「警報の端末設定…」と、アラーム一覧の窓の「端末設定」。Project の設定ではないので、サイドバーの「プロジェクト設定」には置かない。
- 窓（モーダル）に 3 つの欄を縦に並べる: 「履歴の保持」「値の読み直し」「ブザーの音」。
  - 履歴の保持: 日数か件数を選び、値を入れる。いまの件数と最も古いイベントの時刻を示す（いま続いている警報のイベントは期限を過ぎても残ることを添える）。
  - 値の読み直し: 4 つの値。保存するとすぐ使うことを示す。
  - ブザーの音: いまの音（既定のビープか、取り込んだファイルの名前）、代替のときはその理由、「ファイルを選ぶ」「既定に戻す」「試しに鳴らす」（ブザーが鳴っているあいだは押せない）。
- 「保存」で保持と読み直しをまとめて保存する。音の操作はその場で反映する（ファイルの取込みは別の確定を要らない）。
- 権限が無いときは値を読めるが変更できず、理由を示す。ブラウザ版（host が無い）は入口を押せず、理由を示す。
