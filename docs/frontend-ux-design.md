# SCADA フロントエンド UX 設計

作成日: 2026-10-18。設計担当: Astra。対象: `apps/banto-scada`。

本書は、工程図を作る人がキャンバスを見失わずに配置・共有部品編集・表示確認を往復できる Designer と、将来の監視 Runtime の設計案である。**この文書とワイヤーフレームは UI の実装完了を示さない。** 最初に情報配置と編集操作を整え、その後 Hub の読み取り Binding、設備操作へ進む。MES、レシピ、スクリプト、履歴・警報エンジンは現在の編集画面の必須項目にしない。

## 採用方針の更新（2026-10-18）

ユーザー確認により、大枠の画面配置は本書の方向で進め、細部は実際の編集作業を通じて調整する。直近は機能優先とし、サイドパネル / 下部パネルのフローティングとドッキングは後続とする。領域ごとのコンポーネント分離は先に行うが、ドッキング基盤や自由配置レイアウトの保存を先行させない。

リリース前の Project ファイルの後方互換性は保証しない。必要なモデル変更を優先し、旧形式からの migration を新機能の実装条件にしない。新しい現行形式について schema・Rust / TypeScript・サンプル・検証を揃える。正式リリース時の互換性方針は別途決める。

## 3. 利用者・主要タスク・設計原則

| 利用者                     | 達成したいこと                               | UX 上の優先事項                                          |
| -------------------------- | -------------------------------------------- | -------------------------------------------------------- |
| 画面設計者・設備エンジニア | 工程図を組み、複数画面で設備形状を再利用する | 大きいキャンバス、正確な座標、共有変更の影響が分かる     |
| 試運転・保守担当           | タグの割付とデータの意味を確認する           | 値・単位・Quality・更新時刻、未接続理由を同じ文脈で確認  |
| 運転員（後続 Runtime）     | 設備の状態を把握し、許可された操作をする     | 状態と通信品質の区別、誤操作防止、読み取りを妨げない認証 |

設計原則:

1. **中央の工程図を作業の基準にする。** 部品検索や設定を開いても、選択とキャンバスの位置を保持する。
2. **編集対象と影響範囲を先に示す。** 「画面」「配置」「共有定義」「将来の設備 Binding」を名称とパンくずで区別する。
3. **表示・通信・操作の状態を分ける。** プレビューを運転と呼ばず、値がない状態を停止やゼロで代用しない。
4. **段階的に情報を増やす。** 未対応のタブや空の機能ツリーを常設しない。利用可能な操作を中心に置く。
5. **同じ結果へ複数の操作方法を用意する。** ドラッグに加えて一覧・数値入力・キーボードを提供する。

## 4. Designer・表示確認・Runtime

| 項目     | Designer / 編集                         | 表示確認（既存名: 表示プレビュー）     | Runtime（後続）                       |
| -------- | --------------------------------------- | -------------------------------------- | ------------------------------------- |
| 目的     | Project の作成・変更                    | 同じ Project の見た目を確認            | 配布済み Project の監視・許可済み操作 |
| 編集 UI  | Project / Symbol / Inspector / 編集補助 | 編集パネル・ハンドル・グリッドを隠す   | 編集機能を持たない                    |
| データ   | 現状は静的                              | 現状は静的。「表示確認・未接続」を明示 | Hub の値・Quality・接続状態           |
| 設備操作 | 設計設定のみ。現在は未実装              | 常に実行しない                         | 認証・認可・Action 検証の成立時のみ   |
| 切替     | 現在のアプリ内切替                      | 「編集へ戻る」で同じ画面へ             | 起動時 mode。UI 切替では昇格しない    |

提案では、右上に「編集 / 表示確認」の文字付き切替を置く。再生アイコン単独では運転開始と誤認するため使わない。現行の起動時表示プレビューは維持し、編集へ入る入口を明瞭にする。表示確認から戻った際は画面別のズーム・スクロールを復元し、選択解除は既存契約を維持する。

将来、模擬値を使う場合は「模擬データ」と常時表示し、ライブ接続とは別のデータ源として扱う。静的サンプルを Good と表示しない。正式 Runtime は同一 executable の起動 mode として分離し、Tauri capability と Rust domain の双方で編集を拒否する上流方針に従う。

認証の実装は industrial 側の修正完了後。現段階のローカル編集はログイン不要。将来の運用ではユーザー管理を必要とし、再起動後は匿名の閲覧専用監視を開く。操作時に権限を確認し、ログアウトしても監視を継続する。この方針を現在の表示確認だけで実現したとは扱わない。

## 5. 情報構造と領域寸法

基準は 1440×900 CSS px、通常密度。領域寸法は画面設計上の初期値で、Project の design unit とは別。

| 領域           | 初期寸法 / 制約                                       | 内容・スクロール                                                                                                    |
| -------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| アプリバー     | 高さ40px                                              | Project 名、未保存表示、ファイル、編集、表示、挿入、ヘルプ、モード切替。テーマは表示メニュー内                      |
| 編集ツールバー | 高さ40px                                              | JSON 保存、Undo / Redo、選択、矩形・楕円・線・テキスト、整列、グリッド / スナップ。優先度の低い操作はメニューへ     |
| 左ペイン       | 幅264px、可変220〜360px                               | 上に Project / 図形一覧、下に検索付き Symbol。境界を上下に動かせる。各見出し・検索を固定し本文だけスクロール        |
| 左上 / 左下    | 利用可能高の45% / 55%、それぞれ最小160px              | 低い画面では上下分割を「Project / Symbol」タブへ切替                                                                |
| 中央           | 幅最小480pxを確保                                     | 開いている画面・定義のタブ32px、必要時ルーラー20px、キャンバス。縦横スクロールは中央内だけ                          |
| 右 Inspector   | 幅304px、可変280〜400px                               | 対象名・対象種別を固定し、本文を縦スクロール。初期は配置と見た目だけ展開                                            |
| 下部ドック     | 初期は閉。展開時220px、最小160px、作業領域高の40%まで | 中央の下に「タグ / 診断」。タブ・検索・列見出し固定、表の本文をスクロール。接続未実装段階ではタグタブ自体を出さない |
| ステータス     | 高さ24px                                              | 対象、選択数、座標 / サイズ、ズーム。通信状態は接続機能導入後に追加                                                 |

以下の可変幅・折りたたみは操作領域の完成形の案であり、直近の全機能の前提ではない。フローティング / ドッキングとそのレイアウト復元は、編集機能を揃えた後に検討する。直近は固定配置で作業できる状態を優先する。

左右は折りたためる。折りたたみ後も名前付きの復帰ボタンを残し、キーボードから開ける。開閉・幅・下部タブ・ズーム等は workspace state とし、Project JSON と履歴に含めない。将来のローカル復元は Banto UI settings を使い、保存できない場合も作業を継続する。開いた Project に存在しない画面 ID の UI 状態は破棄する。

### ナビゲーション

- Project ルート配下は、まず「画面」「Symbol」。画面に追加・複製・設定・削除の操作を持たせる。後続の Binding 導入時に「タグ参照」、Equipment 導入時に「設備」を追加する。
- 「図形一覧」は現在の画面または共有定義の内部図形を表示する。Project ツリーの全階層へ全オブジェクトを常時展開しない。選択はキャンバスと同期する。
- 中央タブは作業対象へのショートカット。タブを閉じても画面・定義を削除しない。削除は別の明示操作にする。タブ順は workspace state とし、Project の画面順を暗黙に変更しない。
- Symbol は図形サムネイルと名前の2列グリッドを基本とし、名前で検索できる。共有定義のプレビューと実際の配置色が異なる現仕様を説明する。
- アラーム・トレンドは機能実装後に追加する。レシピ、スクリプト、MES、Datasets は後続の能力に応じて追加し、空ノードを並べない。

### キャンバス

提案するズーム範囲は25〜400%、100%と「全体に合わせる」を常設する。100%は1 design unit = 1 CSS px の基準とし、現在の fit 表示との違いを明示する。キャンバスの表示変換だけを変え、座標や Symbol 定義を変更しない。倍率変更は viewport 中央、ポインタ操作ではポインタ位置を基準とする。

通常のホイールはスクロール、専用の倍率ボタンでズームする。ブラウザの `Ctrl / ⌘ + +/-/0` とピンチによるページ拡大を奪わない。将来の Space + ドラッグによるパンはキャンバスにフォーカスがある時だけ有効にする。ルーラーは design unit を表示し、非表示にできる。グリッド表示と吸着は別トグルとし、既存の初期値はどちらも無効のまま。

## 6. 重要操作フロー

### 画面を作って表示を確認する

1. 「編集」へ入り、Project の「画面を追加」で空画面を作る。既存どおり現在の画面サイズを引き継ぐ。
2. Symbol を選び「画面へ配置」。提案では現在見えているキャンバス中央へ配置し、新しい配置を選択する。ドラッグ配置は後から追加し、ボタンの経路を残す。
3. 配置・サイズ・配管経路を編集する。ドラッグ中は一時表示、離した時に1操作として確定する既存挙動を維持する。
4. Inspector で数値を入力して「適用」。不正な欄の直下に理由を示し、入力と選択を保持する。
5. 「表示確認」で枠なしの同じ画面を確認し、「編集へ戻る」で作業位置へ戻る。
6. 「JSON 保存」でファイルをダウンロードする。ブラウザ内の適用とファイルへの持出しを区別して表示する。

### 配置を変える・共有定義を変える

| 対象             | 入口・表示名                                   | 変更の影響                                         |
| ---------------- | ---------------------------------------------- | -------------------------------------------------- |
| 画面上の配置     | クリック →「配置: ポンプ」                     | その配置の位置・サイズ・単色。定義と他の配置は維持 |
| 共有 Symbol 定義 | Inspector の「共有定義を編集」またはライブラリ | 全画面の参照配置へ形状変更を反映                   |
| 定義の複製       | ライブラリの「定義を複製」                     | 別 ID の定義・内部図形を作る。既存配置の参照は維持 |

共有定義編集では「Project › Symbol › ポンプ」と「共有定義を編集中・使用中 N 配置 / M 画面」を固定表示する。画面の編集タブと同じ名前でも、アイコンと対象種別を併記する。「画面へ戻る」は編集の取消ではない。既存どおり適用済み変更は Project 内へ即時反映し、戻る時に二重の保存ボタンを設けない。

誤って全配置を変えないよう、入口で「形状の変更は N 配置に反映。別の形にしたい場合は定義を複製」と短く示す。毎回の頂点編集に確認ダイアログは挟まない。未使用の定義を削除する時は対象を確認し、使用中なら削除不可の理由と参照先を表示する。既存配置を複製定義に差し替える機能は未対応であり、現状は複製定義を新規配置する。

### タグを割り付ける（後続）

1. 表示対象の Binding 欄から「タグを選択」。下部タグドックを開き、対象プロパティと必要な型を固定表示する。
2. Hub catalog の接続 → グループ → タグを探索、または `external_name`・表示名・説明で検索する。
3. 候補を選び、型・単位・Quality・読み書き属性を確認して「割付」。ドラッグやダブルクリックも同じ型検証へ通す。割付先が不明なダブルクリックでは詳細を開くだけにする。
4. 適用後は対象の Binding 欄へフォーカスを戻す。互換性のないタグは割付せず、例として「運転状態には bit が必要です。選択タグは f32 です」と示す。

タグを選ぶだけでは書込み Action を作成しない。Hub の `external_name` を永続参照し、PLC アドレスや内部数値 ID を SCADA の Binding identity にしない。参照切れを類似名へ自動再割付しない。

## 7. Inspector の段階表示

直近はタブを増やさず、対象名の下に「配置」「見た目」「詳細」の折りたたみセクションを置く。Binding 実装時に「表示・配置 / データ」、Action 実装時に「イベント・操作」を追加する。参考画像の「基本・動作・イベント」を未実装のまま並べない。

| 選択状態      | 初めに示す内容                    | 詳細・注意                                                             |
| ------------- | --------------------------------- | ---------------------------------------------------------------------- |
| 選択なし      | 編集中の画面名・幅・高さ          | 画面サイズ変更は図形を拡大縮小しない。領域外の図形を保持し診断に示す   |
| 図形1つ       | 種類、X / Y、幅 / 高さ、色        | UUID はコピー可能な詳細欄。回転は未対応なので入力欄を出さない          |
| Text          | 位置・領域・文字列・色            | 現状は高さが文字サイズに影響し、幅で自動折返ししないことを補足         |
| 折れ線 / 配管 | 位置、線幅、色、矢印              | 頂点テキスト編集は詳細へ。幅 / 高さの汎用リサイズ欄を出さない          |
| Symbol 配置   | 位置・表示サイズ・配置色、定義名  | 「共有定義を編集」と使用数。Equipment と同一視しない                   |
| 複数選択      | N個選択、移動量、整列、複製、削除 | 現状の一括対応範囲だけ表示。未対応の混在プロパティを編集可能に見せない |

数値欄には design unit、色欄にはスウォッチと文字値を併記。フォームの未適用入力は Project の変更と区別する。未適用入力があるまま対象を切り替える場合、「適用して続行 / 入力を破棄して続行 / キャンセル」を選べる（2026-10-18 実装）。複数フォームは全件を事前検証し、不正値があれば入力を保持して操作を中止する。Enter はそのフォームの適用、Esc はまず現在の操作・オーバーレイを閉じる。暗黙の blur 保存は導入しない。

後続の動的プロパティには「固定値 / タグ / 式」を明示する。値が固定なのか Binding により変化するのかを色だけで判別させない。Symbol の単色描画を状態別・多色へ拡張するには schema / renderer の別設計が必要。

## 8. タグ・Quality・接続状態（後続）

下部タグ表の標準列は「外部名 / 型 / 値 / 単位 / 品質 / 更新時刻 / 割付数」。説明・読み書き属性・source kind・Hub 接続先は追加列または詳細へ置く。PLC アドレスの登録・編集は Hub の責務。SCADA に PLC 設定フォームや直接接続テストを作らない。

| 状態                  | 表示                                                        | 操作上の扱い                                     |
| --------------------- | ----------------------------------------------------------- | ------------------------------------------------ |
| 静的表示・未割付      | `--` と「未割付」、または「固定値」                         | 正常値や停止状態に見せない                       |
| Hub 未接続 / 再接続中 | 共通の接続バナーと対象値の品質表示                          | 古い値を現在値扱いしない。再接続中に書かない     |
| 名前未解決            | `--`「タグが見つかりません」                                | 外部名と該当配置へのリンクを診断に示す           |
| 型不一致 / 評価失敗   | `--`「型不一致」等                                          | 対象表示だけを不成立にし、他の図形は描画する     |
| Good                  | 値 + 単位。詳細に更新時刻                                   | Quality と運転 / 停止状態は別表示                |
| Stale                 | 保持値があれば値 +「更新停止」+ 最終更新時刻。なければ `--` | 値だけを通常色で残さない                         |
| Bad                   | 主表示は `--` +「データ異常」                               | 最終正常値を出す場合は詳細に「過去値」として示す |
| 模擬データ            | 対象・接続に「模擬」バッジ                                  | ライブと混在しても出所が分かる                   |

Quality の判定は Hub / 共通評価契約に従い、画面ごとに独自の閾値を作らない。切断検知から Stale へ遷移する時間等は接続契約確定時に決める。ネットワークの再試行は一か所に集約し、タグごとの同一トーストを大量発生させない。

診断には対象・理由・修正先を一覧表示する。未解決 Binding があるだけで Project 全体の表示を禁止するゲートは設けない。一方 Action の対象・引数・権限が成立しない場合は実行せず、将来の execution record / audit に理由を記録する。

## 9. 将来の Runtime と設備操作

Runtime の通常画面は監視キャンバスと画面ナビゲーションを中心にし、画面名・接続・時刻・閲覧専用状態を確認できるようにする。異常表示と通信異常を別の意味で表現する。設備を選ぶと Faceplate に状態・値・権限に応じた操作をまとめる。

運転・停止ボタンを静的 Symbol へ直結しない。Action 実装時は「対象設備 / 要求する操作 / 現在状態 / 実行可否理由」を示し、権限がある場合にのみ明示操作を受け付ける。確認の強さは Action の性質と運用要件で決める。「要求を送信」と「設備が運転状態になった」は別結果とし、応答待ち・失敗・タイムアウトを示す。成否不明の書込みを自動再送しない。

PLC が制御権限を持ち、SCADA からの要求は Hub の認可・書込み経路を通る。画面のボタン表示だけを権限境界にしない。詳細な操作契約と認証は後続であり、この UX 文書だけを根拠に設備書込みを実装しない。

## 10. 視覚・アクセシビリティ

アプリ外枠は Banto の light / dark / system と既存トークンを使う。現行のキャンバス背景は Renderer 内の固定色 `#0b1220` で、schema 0.2.0 に背景色フィールドはない。Project に保存された図形色と、この固定背景はアプリテーマを変えても維持する。背景色を Project ごとに保存する機能は schema の追加が必要な後続機能とする。リリース前の旧形式の移行処理は必須にしない。外枠とキャンバスの境界を明確にする。

- 選択・フォーカスにはテーマのアクセント、注意には warning、エラーには danger の役割を使う。運転状態の色とは別にラベルや記号を添える。
- 「運転 / 停止 / 異常 / 不明」を文字・アイコン・必要に応じた線種で区別する。赤・緑の対だけに依存しない。停止色は設備や運用標準で意味が異なるため全設備へ固定しない。
- 通常の UI 文字は14pxを基準、補助情報は12px以上、行高は1.4以上。コントロールは通常32px以上、タッチ対象は44px以上を目標とする。
- 通常文字はコントラスト4.5:1、境界・フォーカス等の重要な非文字要素は3:1を受入基準とする。Project が任意に設定する配色は別途診断候補とし、外枠の達成と混同しない。
- ハンドルの見える大きさは既存同様に画面上で一定とし、ヒット領域を広げる。狭い図形では一覧選択・数値入力を代替手段にする。
- アイコンのみの操作には accessible name とツールチップ。選択対象、無効理由、保存失敗等は支援技術で読める。値の連続更新を毎回 live region で読み上げない。
- パネル移動・折りたたみを導入する際はキーボードでも実行でき、閉じた内容へ Tab が入らない。分割線はフォーカス可能にして方向キーで寸法変更、Home で既定値へ戻せるようにする。
- 点滅は既定で使わず、動きを減らす OS 設定へ追従する。警報一覧や履歴の UX はその機能を設計する段階で詰める。

## 12. 適用・未保存・破壊操作

既存では「適用」はブラウザ内の Project 更新、「JSON 保存」はダウンロード。自動保存・外部ファイルの上書き・再起動後の復元は未実装。2026-10-18 に内容比較による変更表示、未適用入力の保護、JSON 置換確認、ページ離脱確認を実装した。

実装の表示は「未書き出しの変更あり」「最終書き出し要求 HH:mm」。ダウンロードの場合は「JSON のダウンロードを開始しました」と通知し、実ファイル書込みの成功や保存先を確認できたように表現しない。後続 host が保存成功を返せる場合にのみ「保存済み」と表示する。

変更状態は最後に読み込んだ / 書き出した内容との比較で算出する。Undo / Redo は revision を増やす既存契約があるため、revision だけで変更有無を判定しない。比較から revision と UI 状態を除き、保存内容の同一性を判定する。ブラウザでの書き出し基準は「ダウンロードを要求した内容」であり、ファイルの実在保証ではない。

| 操作                    | 保護方針（外部変更・競合以外は実装済み）                                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 図形削除                | 1操作として Undo 可能にし、通常は確認を挟まない                                                                                        |
| 画面削除                | 名前・含む配置数を示して確認。最後の1画面は削除不可                                                                                    |
| 定義削除                | 参照中は不可。未使用でも定義名を確認                                                                                                   |
| JSON 読込・サンプル置換 | 読込と検証を先に行い、未書き出し変更があれば「JSONを書き出す / 破棄して開く / キャンセル」。書き出し後は自動置換せず利用者が継続を選ぶ |
| 不正ファイル            | 現在の Project・履歴・表示を保持し、対象フィールドと理由を示す                                                                         |
| ページ離脱              | 変更がある間はブラウザの離脱確認を補助として利用。タブ破棄時の復旧保証にはしない                                                       |
| 外部変更・競合          | 正式 package / host 導入後。上書き前に競合を明示し、現在の JSON ダウンロードへ未実装の競合処理を装わない                               |

通常のドラッグ成功ごとにトーストを出さず、選択位置と状態欄の変化で結果を示す提案とする。読込・書出し・破壊操作・検証失敗は通知する。エラーの詳細は対象欄または診断に残し、トーストが消えても確認できる。

## 15. schema と契約への影響

現行 JSON は **0.2.0**。未知フィールドを拒否するため、将来機能を便宜的な属性として勝手に追加しない。

| 変更                                           | schema 変更     | 契約上の条件                                                                                     |
| ---------------------------------------------- | --------------- | ------------------------------------------------------------------------------------------------ |
| パネル・メニュー・検索・タブ・ズーム・ルーラー | 不要            | workspace state。Project export / revision / Undo に含めない                                     |
| 未保存表示・書き出し基準・フォームの入力管理   | 不要            | ローカルの内容比較。ファイル保存成功と区別                                                       |
| 範囲選択・表示中領域への配置                   | 通常は不要      | 既存座標と選択 UI を使う。共通コマンドと hit test の検証は必要                                   |
| Symbol の配置 / 定義編集・複製                 | 既存0.2.0で対応 | 全参照反映・単色・入れ子禁止・参照中削除禁止を維持                                               |
| 画面タブの順                                   | 不要            | workspace の順。保存画面順・起動画面とは別                                                       |
| 保存される画面順の並べ替え                     | 不要            | 現行の `screens` 配列順が保存・読込時の表示順。並べ替え command / history / UI を追加する        |
| Project ごとのキャンバス背景色                 | 必要            | 現行は Renderer の固定色。背景フィールドと描画を追加する。リリース前の旧データ移行は必須にしない |
| 起動画面・保存グループ・回転・機器への配管接続 | 必要            | model / Rust / TS / renderer を揃える。旧形式の migration は必須にしない                         |
| TagBinding・型付き slot・Equipment・動的表示   | 必要            | `external_name`、型・Quality、未解決、read/action 分離を共通契約にする                           |
| 多色 Symbol・状態別表現・テキストの新しい組版  | 必要            | 新しい描画仕様と現行モデルを揃える。既存ファイルとの互換性は保証しない                           |
| Action・運用mode・保存 package                 | 要個別設計      | Project 属性と host / deployment 設定を分離。認証情報を Project へ保存しない                     |

schema を変える段階では現行のバージョン・`minRuntimeVersion`・モデルを揃え、共通 fixture で Rust / TypeScript の一致を確認する。リリース前の旧形式の読込・移行実装は必須にせず、必要な形式変更を許容する。現行形式の検証は維持し、動作属性を検証対象外のフィールドとして混入させない。
